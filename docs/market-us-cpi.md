# CPI и базовый CPI США

Этап после merge #150. Ветка `feat/us-cpi-core-cpi`, база main
`65342d2d48ecbf367f497c0dcb98ebe94747f748`. Только четыре показателя CPI; PPI — следующий отдельный PR.

## Источник и значения

Источник — существующее ведомство BLS, бесплатные датированные
[архивы CPI](https://www.bls.gov/bls/news-release/cpi.htm).
Таблица 1 CPI-U, U.S. city average: `All items` и `All items less food and energy`.
Текущий BLS API содержит текущие версии сезонно скорректированных индексов и не доказывает,
какая цифра была опубликована первоначально. Поэтому CPI больше не вычисляется из этого API.
Остальные поддерживаемые BLS-показатели продолжают использовать существующий batch.

| Показатель / code | Факт | Предыдущее значение | Сезонность / серия |
|---|---|---|---|
| CPI м/м / `us_cpi` | Явное месячное изменение в Table 1 | Предыдущий месяц той же таблицы, в версии текущего релиза | SA / CUSR0000SA0 |
| CPI г/г / `us_cpi_yoy` | Явное 12-месячное изменение в Table 1 | Явное сравнение с предыдущим месяцем в тексте; иначе один сохранённый подтверждённый релиз предыдущего месяца; иначе NULL | NSA / CUUR0000SA0 |
| Базовый CPI м/м / `us_core_cpi` | Явное месячное изменение без еды/энергии | Предыдущий месяц той же таблицы | SA / CUSR0000SA0L1E |
| Базовый CPI г/г / `us_core_cpi_yoy` | Явное 12-месячное изменение без еды/энергии | Явное сравнение в тексте с подтверждённым контекстом периода; иначе сохранённый подтверждённый релиз предыдущего месяца; иначе NULL | NSA / CUUR0000SA0L1E |

Предыдущее значение может отражать пересмотр, явно опубликованный в текущем релизе. Оно не заменяет
первоначальный факт старого события. До релиза previous заполняется только из подтверждённого
датированного релиза непосредственно предыдущего периода, без дополнительных загрузок.

Серверная read-only проверка 05.11.2026: архив `cpi_10142026.htm` HTTP 200.
Релиз 14.10.2026, 08:30 America/New_York, период сентябрь 2026:
CPI м/м +0.6% / previous +0.4%; CPI г/г 3.7% / 3.4%; базовый м/м +0.3% / +0.3%;
базовый г/г 2.6% / 2.4%. Сохранён неизменённый заголовок и Table 1 как offline fixture.
Это проверка реальной исторической публикации, а не утверждение о записи этих цифр в production.

## Проверки соответствия и ограничения

- Проверяются дата embargo, отчётный месяц заголовка и таблицы, CPI-U / U.S. city average,
  точные названия двух строк, единицы percent change, SA/NSA и сравниваемые месяцы/год.
- Значения берутся непосредственно из опубликованных процентов, не рассчитываются по округлённым индексам.
  Неизвестное значение не становится нулём; другой период/стадия не принимается.
- Разбор previous г/г намеренно строгий. Изменившаяся формулировка оставляет previous пустым,
  если нет ровно одного подходящего подтверждённого старого результата. Это не мешает записи факта.
- `result_meta` сохраняет точный период, серию, единицы, сезонность, URL архива, `vintage=release`
  и официальное время релиза. Время скачивания не выдаётся за версию данных.
- Явно помеченный corrected/reissued release отклоняется. Архив не является криптографическим
  доказательством неизменности: незаметное исправление BLS невозможно обнаружить при первом скачивании.
  Уже сохранённый факт не пересматривается автоматически из позднего CPI payload.
- HTTP/сеть/HTML вместо релиза/смена разметки дают закрытую диагностику `market_feed_runs`;
  событие остаётся, непроверенный факт пуст, другие источники продолжаются. Защита BLS не обходится.
- Исторический backfill не добавлен. Уже сохранённые CPI ID/значения/history не удаляются и не
  перекодируются. Старое provenance несовместимого формата не заменяется автоматически; конфликт
  фиксирует `0012`. Для старых подозрительных значений потребуется отдельная проверка владельцем.

## Идентичность и бюджет запросов

Старый `us_cpi` остаётся CPI м/м с тем же ID и исходным DB title для точного adoption legacy.
Три новых code дают самостоятельные стабильные ключи source/country/code/period/stage.
Период берётся из существующего проверенного расписания BLS, а не вычисляется из даты релиза.
Ручная проверенная поправка даты/отмены CPI распространяется на четыре строки; их ID/period не меняются.
Архив выбирается по текущей дате публикации в New York, а не по исходному ID перенесённой записи.

Один существующий BLS slot выполняет **либо** один archive GET для четырёх CPI, **либо** один
существующий API batch для остальных. Общий throttle учитывает оба журнала, интервалы не меняются.
При смешанном ожидании чередуется менее недавно выполненная работа, включая неудачные попытки.
Нет второго запроса для y/y previous, дополнительных cron/polling или новых ключей/зависимостей.
При сбоях одна группа может получить факт на следующем штатном интервале; это предпочтительнее
увеличения частоты. Окно повторов остаётся существующим — 7 дней.
