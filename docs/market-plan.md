### 3.1 Что реально можно бесплатно

| Категория | Показать бесплатно | Свои свечи для Replay и бэктеста |
|---|---|---|
| **Крипта** | Виджеты; свои котировки из публичных данных бирж (Binance и др.) без ключа | **Да:** публичные свечи бирж. Условия Binance для показа на коммерческом сайте нужно сверить; у архивов Binance Vision свои условия — разрешены, например, «потребительские программы» `проверить` |

Исторические данные Dukascopy бесплатны для загрузки, но право распространения **не подтверждено** |
| **Индексы** | Виджеты (часть с задержкой) | Нет бесплатного с правом показа; у бирж и провайдеров отдельные лицензии на индексы |
| **Сырьё, металлы** | Виджеты | Как форекс: платно для показа |
| **Облигации, доходности** | Виджеты | Ежедневные доходности казначейства США — официальные публичные данные (кривая доходности) `проверить` |

**Идея, которая снимает вопрос лицензии: «Свои данные».** Человек сам загружает свечи своего брокера (MT5 и другие платформы умеют выгружать историю в CSV). Данные его, видит их только он — как скриншоты в журнале. С ними работают Replay и бэктест по **любому** инструменту без платного провайдера. Импорт CSV у нас уже есть для сделок, мастер можно повторить для свечей.

### 3.2 Платные варианты (на будущее, когда будет доход)

- Twelve Data, Massive (бывший Polygon), Finnhub и другие: цены и права на показ различаются по тарифам; у многих показ внешним пользователям — только в бизнес-тарифах с ценой по запросу.
  - У Finnhub экономический календарь **не входит** в бесплатный план.
  - Все цифры — из сторонних обзоров, `проверить` перед решением.
- Выбирать по трём вещам: право показа пользователям, история минуток для Replay, цена.

### 3.3 Что хранить и кэшировать на сервере

- **Свечи для Replay и бэктеста:** не таблица на каждую свечу (миллионы строк не влезут в бесплатный Supabase), а **файлы по месяцам** в хранилище (`<инструмент>/<таймфрейм>/<год-месяц>`), сжатые. Хранить минутки, старшие таймфреймы собирать из них. Лимиты бесплатного Supabase (база и хранилище) `проверить`.
- **Кэш котировок для карточек** (если не виджеты): одна запись на инструмент, обновление по расписанию; браузер ходит к нам, а не к провайдеру. Ключи провайдера — только в секретах сервера.
- **Календарь и новости** (свои, этап 4): события и заголовки со ссылками, хранить 30–90 дней (число — твоё решение).
- **Свои данные пользователя:** его файлы — в его папке, правила как у скриншотов (RLS, лимит места).
- **Не кэшировать то, что запрещено:** условия FRED API запрещают хранить и кэшировать его содержимое → макро берём напрямую из первоисточников (BLS, BEA, казначейство США и др.), где это разрешено `проверить`.

## 5. Replay и бэктест

**Главное (уточнение владельца 2026-10-28):** бэктест **универсальный**. Каждый проверяет **свою** стратегию. Правило владельца sweep → displacement → FVG → MSS — **готовый пример (пресет)**, не встроенная логика.

### 5.1 Replay

- Выбираешь инструмент, таймфрейм, дату и время (например, «открытие Лондона 12 марта»).
- График показывает историю до этой точки, будущее скрыто.
- Кнопки:
  - шаг на 1 свечу вперёд;
  - проигрывание со скоростью ×1…×10;
  - пауза;
  - прыжок к открытию сессии;
  - смена таймфрейма — старший собирается из минуток, без «подглядывания» вперёд.
- Работает на данных этапа 2: крипта с бирж или «Свои данные» пользователя.

### 5.2 Три уровня бэктеста

| Уровень | Что делает пользователь | Что делает платформа | Когда |
|---|---|---|---|
| **(a) Ручной бэктест в Replay** | Сам ставит вход, стоп и тейк на графике (рыночный или лимитный вход), может двигать стоп в безубыток или закрыть руками | Исполняет по следующим свечам с учётом спреда, комиссии и проскальзывания (5.5). Считает результат в R и деньгах. Сохраняет сделку в **тренировочный журнал** с пометкой «тренировка», стратегией, сессией и скриншотом графика. Строит тот же отчёт, что для автоматического бэктеста (5.6) | Этап 2 (вместе с Replay) |
| **(b) Конструктор правил без кода** | Собирает стратегию из блоков: условия входа, фильтры, стоп, тейк, сопровождение, риск. Берёт пресет и меняет числа | Проверяет стратегию, прогоняет её по истории движком (5.4), показывает отчёт и каждую сделку в Replay с разметкой: какие блоки сработали | Этап 3 |
| **(c) Свои скрипты** | Пишет логику сам (например, на JavaScript) | Запускает только в изолированной песочнице (5.8) | Позже, отдельный план с разбором безопасности и твоим решением |

**Тренировочные сделки и сделки бэктеста — без монет и XP.** Они не попадают в статистику реального журнала, дашборд, Process Score, задания и достижения.

### 5.3 Стратегия как данные (формат)

Стратегия бэктеста — **JSON-документ с версией формата**. Это не код, поэтому его безопасно хранить, синхронизировать, проверять и показывать. Тот же документ читают конструктор (b), движок, отчёт и разметка в Replay.

```json
{
  "schemaVersion": 1,
  "id": "bt_x1",
  "name": "Sweep → MSS → FVG (пример)",
  "preset": "smc_sweep_mss_fvg",
  "market": { "timeframe": "M5", "context": [{ "timeframe": "H1", "use": "bias" }] },
  "direction": "both",
  "setup": {
    "steps": [
      { "id": "s1", "block": "liquiditySweep", "params": { "level": "swing", "swingLength": 3, "closeBack": true } },
      { "id": "s2", "block": "displacement", "after": "s1", "withinBars": 3, "params": { "bodyAtr": 1.5, "atrLength": 14 } },
      { "id": "s3", "block": "fairValueGap", "after": "s2", "withinBars": 0, "params": { "minSizeAtr": 0.2, "source": "s2" } },
      { "id": "s4", "block": "structureShift", "after": "s1", "withinBars": 10, "params": { "kind": "mss" } }
    ],
    "filters": [
      { "block": "session", "params": { "sessions": ["london", "newyork"] } },
      { "block": "weekday", "params": { "days": [1, 2, 3, 4, 5] } }
    ]
  },
  "entry": { "type": "limit", "at": { "zone": "s3", "level": "mid" }, "expireBars": 10 },
  "stop": { "type": "beyondPoint", "at": { "extreme": "s1" }, "bufferPoints": 2 },
  "target": { "type": "rMultiple", "value": 2 },
  "management": { "breakevenAtR": null, "timeExitBars": null, "maxTradesPerDay": 2 },
  "risk": { "mode": "percent", "value": 1, "startBalance": 10000 },
  "costs": { "spreadPoints": null, "commissionPerTrade": null, "slippagePoints": null }
}
```

- **Блоки** — закрытый список с описанными параметрами. Каждый блок — небольшая функция движка с тестами.
  - структура: swing high/low, liquiditySweep (swing / максимум-минимум прошлого дня или сессии / диапазон Азии), displacement, fairValueGap, orderBlock (позже), structureShift (BOS / MSS);
  - индикаторы: MA (SMA/EMA), RSI, ATR, Bollinger, VWAP (позже);
  - цена: пересечение уровня или MA, пробой диапазона, свечной паттерн (поглощение, пин-бар);
  - время: сессия, окно времени, день недели, исключить ±N минут вокруг событий календаря (когда будет свой календарь);
  - контекст старшего таймфрейма: направление по структуре или MA.
- **Связи:** `after` + `withinBars` задают порядок «сначала A, потом B не позже N свечей». Есть и простые «и / или / не» для фильтров.
- **Вход:** рыночный на открытии следующей свечи, лимитный у зоны (край / середина), стоп-ордер на пробой.
- **Стоп:** за экстремумом шага, ATR × k, фиксированные пункты, край зоны.
- **Тейк:** R-кратное, противоположная ликвидность, фиксированные пункты.
- **Сопровождение:** безубыток при xR, выход по времени, максимум сделок в день. Частичная фиксация — позже.
- **Риск:** фиксированный % от счёта или фиксированная сумма. Результат всегда и в R, и в деньгах.
- **Проверка документа:** перед запуском — по схеме (типы, допустимые значения, ссылки `after` на существующие шаги, без циклов), с понятными сообщениями. Для проверки нужен либо свой небольшой валидатор, либо библиотека проверки JSON-схем — **новая зависимость только с твоего согласия** (AGENTS.md).
- **Версия формата:** `schemaVersion` + миграция старых документов при чтении — как схема журнала.
- **Хранение:** в стратегии журнала появляется необязательное поле `backtest` с этим документом. Стратегии уже хранятся в облаке как JSON до 256 КБ (`journal_strategies.data`, 0004), поэтому **миграция не нужна**, синхронизация та же.
- **Пресеты** — такие же документы с пометкой «пример, не рекомендация»:
  - твой «Sweep → displacement → FVG → MSS»;
  - простые учебные: пробой диапазона Азии, пересечение двух MA, откат к EMA по тренду старшего таймфрейма.

### 5.4 Движок: как исполняет и где работает

**Как исполняет:**
- Одна чистая функция: стратегия + свечи + издержки + настройки → список сделок и журнал событий.
  - события: «шаг s1 сработал на свече …», «ордер выставлен», «исполнен», «стоп» — по ним рисуется разметка в Replay;
  - функция не ходит в сеть, не читает хранилище и не зависит от времени — одинаковый вход всегда даёт одинаковый результат.
- Идёт **свеча за свечой**, как Replay:
  - индикаторы считаются только по закрытым свечам;
  - свеча старшего таймфрейма доступна только после закрытия;
  - **будущее не видно** — это проверяется отдельными тестами «без подглядывания».
- **Если внутри одной свечи достигнуты и стоп, и тейк:**
  - при наличии минуток — смотрим минутки;
  - иначе — **по умолчанию считаем, что первым был стоп** (осторожная оценка; можно переключить).
- **Исполнение:**
  - рыночный вход — по открытию следующей свечи + проскальзывание;
  - лимит — при касании уровня с учётом спреда;
  - стоп — по уровню + проскальзывание; при гэпе — по цене открытия.

**Где работает — в браузере, в фоновом потоке (Web Worker).** Почему:
1. **Бесплатно** (D-21): сервер ничего не считает, нагрузка не растёт с числом пользователей.
2. **Приватность:** «Свои данные» и стратегии пользователя никуда не уходят.
3. **Экран не зависает:** долгий прогон идёт в фоне, есть прогресс и «Остановить».
4. **Работает без сети**, если свечи уже скачаны.
5. Тот же код (чистая функция) потом запустится и на сервере, если понадобится: Scanner (Pack 8.6) или «проверенный результат» для сообщества.

**Ограничения:** на телефоне длинные прогоны по минуткам медленнее. Предупреждаем и предлагаем старший таймфрейм. Предел длины истории за один прогон — число подберём на тестах, это будет заглушка, которую утверждаешь ты.

**Сервер нужен только** для свечей (кэш файлами, 3.3) и для синхронизации стратегий и сохранённых отчётов.

### 5.5 Реалистичность

- **Спред, комиссия, проскальзывание** задаются у стратегии или по инструменту, с подсказкой «узнай у своего брокера». **Готовых чисел мы не придумываем**: поле пустое, пока пользователь не заполнит, и отчёт тогда пишет «без учёта издержек».
  - Спред — в пунктах, покупка по ask, продажа по bid.
  - Комиссия — за сделку или за лот, туда и обратно.
  - Проскальзывание — в пунктах на рыночных и стоп-ордерах.
  - Своп — не учитываем, пишем об этом в отчёте.
- **Обучающий и проверочный отрезки:**
  - история делится по дате на «настройку» и «проверку» (по умолчанию 70 / 30 — заглушка, меняется);
  - отчёт показывает оба отрезка рядом;
  - если на проверке результат заметно хуже — предупреждение «возможна подгонка»;
  - позже — скользящая проверка (walk-forward).
- **Мало сделок** (порог — заглушка, например меньше 30) — предупреждение «выборка слишком мала для выводов».
- **Пометки на отчёте:** «Результаты на исторических данных не гарантируют будущих. Торговля несёт риск потери капитала. Не является финансовой рекомендацией.»

### 5.6 Отчёт (одинаковый для ручного и автоматического бэктеста)

- **Итог:**
  - число сделок, винрейт;
  - средний выигрыш и проигрыш в R, средний RR;
  - ожидание в R на сделку;
  - профит-фактор;
  - итог в R и в деньгах при выбранном риске.
- **Риск:**
  - максимальная просадка в R и в %;
  - самая длинная просадка по времени;
  - самая длинная серия выигрышей и проигрышей.
- **Разбивки:**
  - по сессиям (Азия / Лондон / Нью-Йорк);
  - по дням недели и по часам;
  - по направлению (покупки / продажи);
  - по месяцам.
- **Графики:**
  - кривая капитала (в R и в деньгах);
  - распределение результатов в R;
  - отметка границы «настройка / проверка».
- **Список сделок:** каждая открывается в Replay с разметкой сработавших блоков, входа, стопа и тейка.
- **Экспорт** отчёта и сделок в CSV (как в журнале).

### 5.7 Связь со стратегиями Журнала

- У стратегии журнала вкладка **«Бэктест»**: правила (5.3), последние прогоны, кнопка «Проверить на истории».
- **«Бэктест против реальных сделок»** — две колонки рядом:
  - слева бэктест, справа реальные сделки журнала с этой стратегией за тот же период;
  - винрейт, средний R, профит-фактор, просадка, разбивка по сессиям и дням;
  - простые выводы без советов: «в бэктесте Лондон лучше Нью-Йорка, в твоих сделках — наоборот».
- Позже — **проверка соблюдения правил:** для реальной сделки, если есть свечи этого инструмента и времени, движок отвечает, был ли в момент входа сетап по правилам стратегии («вход по правилам / вне правил»). Это дополняет чек-лист Process Score.
- Тренировочные сделки (ручной бэктест) — третья колонка «тренировка» по желанию.
- Ничего из этого не даёт монет и XP.

### 5.8 Свои скрипты (уровень c) — позже и только в песочнице

**Риски:**
- кража данных (токен входа, журнал) через доступ к странице или сети;
- зависание (бесконечный цикл), забивание памяти;
- вредный вывод на экран (XSS);
- распространение вредных скриптов через Сообщество;
- «сигналы» под видом скриптов (запрещено правилами проекта).

**Как изолировать** (минимум, обсуждается отдельным планом):
- скрипт выполняется в отдельном интерпретаторе внутри WebAssembly (например, QuickJS) в Web Worker на **отдельном источнике** (другой поддомен, изолированная вставка) без доступа к cookies, хранилищу и странице приложения;
- **сеть закрыта** политикой безопасности (CSP);
- лимиты времени и памяти, принудительная остановка;
- на вход — только свечи и параметры, на выход — только данные по схеме (сделки и события), которые приложение проверяет и показывает как текст;
- **скрипты только свои**, обмен в Сообществе — не раньше модерации и отдельного решения;
- на сервере пользовательский код **не запускаем**.

До уровня (c) — внешний аудит или как минимум отдельный разбор с тестами атак.

- Свой дашборд по отчёту 5.6.
- **Без монет и XP**, не смешивается с реальной статистикой.
- Синхронизация с облаком — как журнал. Нужна ли для этого своя таблица — решим в плане этапа 2; это возможная миграция, которую применяешь ты.

## 10. Дополнения владельца (2026-10-28): стратегия необязательна, «Провести бэктест», квесты Рынка

### 10.1 Стратегия необязательна

- **График по умолчанию открывается на последних данных** выбранного инструмента. Он чистый: без стратегии, без разметки.
- В Replay и в ручном бэктесте стратегию можно **не выбирать**:
  - тренировочные сделки без стратегии идут в тренировочный журнал с пометкой **«без стратегии»**;
  - в отчёте и дашборде «Тренировки» есть фильтр: все / по стратегии / без стратегии.
- Стратегию можно привязать позже — к сессии Replay целиком или к отдельной тренировочной сделке.

### 10.2 «Провести бэктест» из стратегии Журнала

- В карточке стратегии Журнала — кнопка **«Провести бэктест»**. Она открывает Replay с этой стратегией:
  - сбоку видны правила стратегии (чек-лист);
  - тренировочные сделки помечаются этой стратегией.
- **Пару и дату старта выбирает пользователь** — так же, как в обычном Replay.
- **Выбор только из доступных данных:** крипта с публичных бирж и «Свои данные» пользователя. Если своих данных нет — подсказка «Загрузи свои данные или начни с крипты» и кнопка с BTC/USDT.
- **Слепой режим** — необязательный переключатель, по умолчанию выключен:
  - случайный инструмент и случайный отрезок из доступных данных;
  - название инструмента, даты и цены на шкале скрыты до конца сессии;
  - в конце — «Показать, что это было» (инструмент и даты).
- **Если по выбранной паре и дате нет данных** — понятное сообщение без технических слов, например: «Нет данных по EURUSD за 12 марта 2025. Выбери другую дату или пару, или загрузи свои данные». Плюс кнопки: «Ближайшая дата с данными», «Загрузить свои данные». То же для пробелов внутри истории (выходные и праздники не считаются пробелом).
- На этапе 3 у этой же кнопки появляется второй путь — «Автоматический бэктест» по правилам конструктора.

### 10.3 Квесты Рынка

**Главное правило:** тренировочные сделки и бэктесты **сами монет и XP не дают**. Награду даёт только выполнение квеста.

**Защита от накрутки** (поверх правил `docs/economy-coins-plan.md`, разделы 5 и 6):

| Риск | Защита |
|---|---|
| Подглядеть будущее и «угадать» | Движок не показывает будущие свечи (5.4). **Пока сделка открыта, отмотка назад запрещена.** Если отмотать назад на уже виденные свечи, сделки на них помечаются «на просмотренных свечах» и **не засчитываются в квесты** |
| Много мелких сделок подряд ради счётчика | Засчитываются только сделки **со стопом**, закрытые не на той же свече, где открыты, не чаще одной на свечу; число в квесте — с потолком в день |
| Повторять квест на результат | Квесты на результат (например, «сделка с RR 1:2») — **разовые, один раз на аккаунт**, как «первые действия»: проверка по тренировочному журналу, включая удалённые записи |
| Править, удалять и создавать заново | Правка, удаление и повторное создание тренировочной сделки ничего не дают (как в журнале) |
| Перевести часы | Действует защита от перевода часов назад (`CLOCK_BACK_TOLERANCE_MS`) |
| Фарм монет за день | Действует **дневной потолок 100 монет** (`DAILY_COIN_CAP`). На Рынке — **только один повторяющийся квест с монетами в день**, остальные повторяющиеся — только XP |
| Повторяющиеся квесты | Проверяют **процесс**, а не результат: число сделок, наличие стопа, заполненный разбор, сравнение с реальным Журналом |

**Почему один ежедневный квест с монетами:** сейчас честный максимум за день — ежедневная награда до 50 + проверяемые задания до 40 = 90. Ещё 10 монет с Рынка дают ровно 100, то есть потолок. Если монет на Рынке будет больше, честный игрок начнёт упираться в потолок. Тогда нужно либо поднять потолок, либо оставить квесты Рынка только с XP — решение владельца.

**Предлагаемые квесты.** Все суммы — **заглушки** по образцу текущих наград, утверждает владелец.

| № | Квест | Тип | Условие (проверяет приложение) | Награда (заглушка) | Правило экономики |
|---|---|---|---|---|---|
| 1 | **Первый Replay** | разовый на аккаунт | Пройти сессию Replay вперёд не меньше 30 свечей | 10 монет, 10 XP | «первое действие» (как `FIRST_ACTION_REWARDS`), вне потолка |
| 2 | **Первая тренировочная сделка** | разовый | Закрытая тренировочная сделка со стопом и тейком, не на просмотренных свечах | 10 монет, 10 XP | «первое действие» |
| 3 | **Сделка с RR 1:2** | разовый, на результат | Тренировочная сделка закрыта по тейку с RR ≥ 2 | 10 монет, 20 XP | разовый квест на результат, один раз на аккаунт |
| 4 | **Первые «Свои данные»** | разовый | Загружен файл свечей, принят проверкой | 10 монет, 10 XP | «первое действие» (по образцу первого импорта) |
| 5 | **Бэктест своей стратегии** | разовый | «Провести бэктест» из стратегии Журнала → не меньше 10 тренировочных сделок с этой стратегией → открыт отчёт | 15 монет, 20 XP | «первое действие» |
| 6 | **Слепая тренировка** | разовый | Слепой режим: не меньше 10 тренировочных сделок, сессия завершена | 10 монет, 15 XP | «первое действие» |
| 7 | **Тренировка дня** | ежедневный, **единственный с монетами** | 5 тренировочных сделок со стопом на разных свечах, не на просмотренных свечах | 10 монет, 40 XP | проверяемое задание дня; потолок 100 |
| 8 | **Разбор тренировки** | ежедневный | После тренировки заполнен разбор сессии: итог и заметка не короче 80 символов «что получилось / что нет» | 25 XP | процесс; только XP |
| 9 | **Неделя тренировок** | еженедельный | «Тренировка дня» выполнена в 3 разных дня недели | 50 XP | процесс; только XP |
| 10 | **Сверка с Журналом** | еженедельный, этап 3 | Открыто сравнение «бэктест против реальных сделок» по стратегии, у которой за неделю есть не меньше 3 новых реальных сделок | 30 XP | процесс; только XP |

Квесты Рынка не отмечаются вручную: их закрывает приложение (решение 4 из `economy-coins-plan.md`). В режиме 16–17 они доступны: денег нет. До 0007 всё считается на устройстве, как остальная экономика. После 0007 сервер пересчитывает по данным.
