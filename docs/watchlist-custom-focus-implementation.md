# WATCH-2D — Custom Market Focus: реализация

Следующий этап WATCH-2E добавляет явно включаемые Custom Session Reminders. См.
[отдельный отчёт о времени и совместимости](watchlist-custom-session-reminders.md).
Описанный ниже OFF отражает состояние WATCH-2D до этого расширения.

22 ноября 2026. Draft PR #217; merge и production deployment не выполнялись.

## Что работает

Один прежний блок после TradingView Quotes. У четырёх селекторов есть компактный
редактор Add/Manage. Пользователь создаёт, переименовывает, выбирает и удаляет свои
POI, MSS, направления и сессии; библиотека общая для инструментов своего локального
аккаунта/Guest. Системные значения не удаляются. До 30 активных значений каждого типа,
название до 160 Unicode code points. Идентичность — UUID, а не название. Дубликаты
имён не объединяются и различаются ID. Удаление требует подтверждения и сохраняет
tombstone; использованный выбор остаётся видимым с пометкой удаления.

Сессия хранит HH:mm начала/конца и IANA timezone; end < start означает следующий
локальный день, start = end отвергается. Это сохранённые гражданские часы, а не
готовое UTC-расписание. Напоминания для custom sessions отключены: правила DST
gap/fold и дней работы пока не реализованы. Стандартные London/New York продолжают
использовать календарь WATCH-2C. Ценового мониторинга и торговых сигналов нет.

## Миграция и атомарность

База `ayra_market_focus_v1` остаётся IndexedDB version 2 с прежними stores. V1→V2
сохраняет шесть исходных отметок. Обычные записи остаются V2; только первый custom
выбор преобразует выбранную запись в V3 внутри одной readwrite-транзакции
entries/preferences/spaces. Четыре поля становятся system/custom references; добавляются
fieldRevisions. Checklist, marks, order, localAlerts/receipts и opaque fields сохраняются.
Конфликт opaque `fieldRevisions`, invalid/future контракт не исправляется догадкой.

Каталог — `preferences.customCatalog` version 1: общая revision, items с UUID,
kind, item revision, label, deleted, session при необходимости. Внешняя preference
остаётся version 1. Все неизвестные поля сохраняются. Никаких SQL/cloud изменений.

Команда проверяет актуальный каталог и запись в транзакции. Первое преобразование
проверяет V2 revision, V3 выбор — fieldRevision и revision выбранного типа. Edit/delete
проверяют item revision, delete дополнительно сравнивает список ссылок. Разные элементы
могут изменяться независимо; устаревшая операция не перезаписывает свежую. Сериализация
локальных изменений не заменяет CAS. Конфликт требует перечитать данные, черновик сохраняется.
Saved появляется только после tx.oncomplete; abort/quota не подтверждаются.

Account generation и purge epoch блокируют поздние операции A→B→Guest→A и возврат
после очистки. Guest не переносится в аккаунт. Удаление инструмента из Watchlist не
удаляет запись и библиотеку. Reset очищает выбор/отметки, сохраняет каталог и названия
чек-листа. Экспорт/очистка профиля охватывают raw V3 и каталог только своего пространства.

## Совместимость и откат

Старый клиент не читает и не редактирует V3-запись, включая её checklist, до обновления.
Обычные V2 инструменты, raw export и scoped cleanup продолжают работать. Старый writer
с отложенным открытием перечитывает запись и отвергает V3, не делая downgrade.
Это ограниченная совместимость, не обещание прозрачной работы всей старой версии.

Для тестов заморожены реальные model/alerts/storage из merge WATCH-2C
`9a3a6e50e210bb7bcf20f86a7c3ce9ae1a3b5b81` в `test-fixtures/market-focus-v2`.
В Chromium запускается старый storage/parser в отдельной вкладке того же origin;
полный старый SPA не запускался. Тест проверяет pending old write, raw export и select.

Откат: предпочтительно оставить V3-readable клиент, отключив редакторы. Возврат к
старому клиенту сохраняет raw данные, но custom-инструменты потребуют обновления.
Автоматического downgrade и готового импорта JSON нет. Reset не удаляет библиотеку;
удаление всех локальных данных профиля остаётся явной разрушительной командой.

## Проверки

- Unit: CAS, лимиты, opaque/future data, abort/quota, account/purge guards, export/cleanup,
  уведомления и последовательные изменения V2→V3. Fake IndexedDB, без production-записей.
- Chromium: 17 новых сценариев, включая реальную V1/V2→V3 миграцию, две вкладки,
  старый writer, rename/delete vs references, offline/reload, account isolation,
  профильный export/Guest cleanup и RU/EN × 360/390/768/1024/1440.
- Напоминания стандартной сессии работают после V3; custom session не создаёт событие.
  Миграция и редакторы не создают ложное completion-уведомление.
- Полные проверки и итоговый SHA публикуются в PR #217 после завершения GitHub CI.

В полном CI `45049100937` обнаружена гонка нового теста профильной очистки: диалог
закрывается до `await deleteGuestData()`, поэтому его исчезновение не означает завершения
IndexedDB-транзакции. Тест исправлен: сначала ожидает существующее сообщение об успешной
очистке, затем проверяет удаление гостевого каталога и сохранность аккаунта. Код очистки,
таймауты и проверки данных не менялись. Результат этого неуспешного запуска: mock-auth
448 PASS + 1 existing skip; fake-Supabase 306 PASS / 1 failed. Финальный CI указан в PR.
