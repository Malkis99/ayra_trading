# Roadmap официального экономического календаря

Снимок от 12 ноября 2026, GitHub main 3dd8c6e. После британских PR обновить статусы по фактическим результатам и остановить расширение до новой команды.

## Доказательства

Различать адаптер в коде, fixtures, официальный HTTP-ответ из Preview, запись в production и результат в интерфейсе. Для каждой проверки фиксировать URL, среду и регион, UTC-время, HTTP/MIME, код/период/стадию/единицы, vintage, ID записи и результат в UI. CI подтверждает тестовые сценарии. Закрытые диагностические данные не публикуются.

P0 — блокирующая точность или доступ. P1 — следующий этап. P2 — расширение. P3 — будущий бюджет или отдельный продуктовый этап.

Бесплатный путь — официальные даты, бюллетени, архивы и API с подтверждёнными правами. У Census/EIA сверять условия ключей, у ONS/BoE — атрибуцию и исключения. Платные агрегаторы, лицензии на перераспределение и прогнозы остаются отдельной бюджетной задачей.

## Возобновление после паузы

1. Сверить свежий main, [архитектуру](market-feeds-plan.md), [целостность](market-event-integrity.md), [0013](market-release-reliability.md), применённые миграции и флаги.
2. Снять read-only состояние cron, горизонтов дат, последних записей, статусов и закрытой диагностики. Обновить доказательства по источнику, записи и UI раздельно.
3. Проверить точный официальный URL в изолированном Preview, права, MIME, лимиты и дату версии. Установить задержку на живом выпуске.
4. Выбрать одну строку очереди, согласовать бюджет, SQL и cron отдельно. Подготовить Draft PR с отказами, повторами, DST, интеграционным тестом и проверкой UI.
5. После одобренного rollout записать результаты фактической публикации и открытые пробелы. Если доказательств не хватает, оставить точный статус и условие возобновления.
