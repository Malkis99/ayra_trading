# План: окно первой настройки Журнала

Статус: **согласован владельцем** (2026-10-19, решения — раздел 9). Код начинается только после того, как владелец напишет «4f пройден». Порядок работ: 4e → 4f → это окно. Флаг синхронизации никому не включается.

Идея: при первом заходе вошедшего пользователя в Журнал — короткое окно настроек. Пользователь сам решает, сохранять ли журнал в облако. Кнопка «Загрузить в облако» перестаёт быть единственной дорогой.

## 1. Что есть сейчас (проверено в коде)

| Настройка | Сейчас | Где хранится |
|---|---|---|
| Показатель R / $ / % | переключатель в Журнале, по умолчанию R | на устройстве (`ayra_journal_unit`) |
| Главный счёт по умолчанию | при добавлении сделки берётся последний использованный счёт | на устройстве (`ayra_journal_last_account`) |
| Часовой пояс | в профиле (знакомство, настройки профиля) | в профиле на устройстве. В облачном профиле есть колонка `timezone`; **синхронна ли она — проверяется в PR 1** |
| Сессия по умолчанию | **нет**: в новой сделке сессия пустая | — |

## 2. Вопросы окна и тексты подсказок «?»

Тексты одни и те же в окне и в разделе «Настройки → Журнал» (один источник в словаре).

**1. Облако** (только вошедшему пользователю при включённом флаге)
- Вопрос: «Сохранять журнал в облако и показывать на всех твоих устройствах?» — **Да / Нет**
- RU: «Да — журнал сохраняется в облако и виден на всех твоих устройствах. Нет — данные остаются только на этом устройстве, облако можно включить позже в настройках.»
- EN: "Yes — your journal is saved to the cloud and shows on all your devices. No — the data stays on this device only; you can turn the cloud on later in settings."

**2. Показатель результата по умолчанию** — **R / $ / %**
- RU: «Так результат показывается в таблице сделок, аналитике и отчётах сразу при открытии. R — результат в рисках сделки, $ — в деньгах счёта, % — в процентах от счёта. Переключить можно в любой момент в самом Журнале.»
- EN: "This is how results are shown in the trade table, analytics and reports when you open them. R — in units of the trade's risk, $ — in account money, % — in percent of the account. You can switch at any time in the Journal."

**3. Главный счёт по умолчанию** (если счёт один — вопрос не показывается)
- RU: «Этот счёт выбирается сам, когда ты добавляешь новую сделку или импортируешь файл. В каждой сделке его можно поменять.»
- EN: "This account is picked by default when you add a trade or import a file. You can change it in any trade."

**4. Часовой пояс и сессия по умолчанию для новых сделок**
- Вопросы: часовой пояс (из профиля) и сессия: Азия / Лондон / Нью-Йорк / Перекрытие / не выбирать.
- RU: «Часовой пояс определяет, к какому дню относится сделка в календаре и итогах дня. Сессия подставляется в новую сделку сама; её можно поменять в сделке.»
- EN: "The time zone decides which day a trade belongs to in the calendar and day totals. The session is filled in for new trades; you can change it in the trade."

Кнопки окна: **«Сохранить»** и **«Пропустить»** (оставить текущие значения). Подпись внизу: «Всё это можно изменить в Настройках → Журнал».

**Как работает «?»**
- Наведение мышью или фокус клавиатурой (Tab) открывают подсказку; на телефоне — нажатие.
- Esc или повторное нажатие закрывают.
- Экранный диктор читает подсказку как описание вопроса.
- На телефоне подсказка открывается под вопросом во всю ширину, не перекрывает кнопки и не выходит за экран.

## 3. Где хранятся настройки и синхронизируются ли

Новая миграция **не нужна**. В облаке уже есть запись настроек журнала из 0004 (`journal_settings`, одна на пользователя, поля в свободном формате). Сейчас там хранится основной проп-счёт, туда же ложатся остальные настройки Журнала без изменения базы.

| Настройка | Где | Синхронизируется |
|---|---|---|
| Показатель по умолчанию, главный счёт, сессия | настройки журнала на устройстве + облачная запись `journal_settings` | **да**, когда облако включено, как остальной журнал («новее побеждает», без диалога) |
| Часовой пояс | профиль | как сейчас; уходит ли он в облачный профиль — проверка в PR 1, результат будет в описании PR |
| **Ответ «Облако: Да/Нет»** | **на каждом устройстве отдельно** | **нет** |

**Почему ответ про облако — на каждом устройстве.** Это решение «отдавать ли журнал этого устройства в облако». На рабочем компьютере можно ответить «Нет», на своём телефоне — «Да». Флаг на сервере остаётся главным: если он выключен, облака нет ни на одном устройстве, что бы ни было отвечено.

## 4. Связь с синхронизацией

| Ситуация | Что делаем |
|---|---|
| «Да», облако пусто, на устройстве есть данные | загрузка **сама**, без кнопки: окно прогресса из 4d («Загружено X из Y», «Отменить»). Резервную копию JSON предлагаем прямо в окне настроек одной кнопкой |
| «Да», данные и тут, и в облаке | то же окно из 4d: «только здесь / только в облаке / отличаются», отличающиеся — через диалог из 4c |
| «Да», на устройстве пусто, в облаке есть | скачивание само с уведомлением «Журнал загружен из облака» (как в 4d) |
| «Нет» | только на устройстве: ни отправки, ни скачивания, значок облака не показывается. В «Настройки → Журнал» есть переключатель «Облако» и кнопка «Загрузить в облако» |
| Флаг выключен | вопрос про облако не показывается; остальные настройки работают у всех |
| Гость | окно не показывается; данные гостя в облако не уходят |

Технически ответ «Нет» для движка синхронизации работает как выключенный флаг, но только на этом устройстве: очередь не копится, облако не читается. Миграций это не требует.

## 5. Кому показывать окно

- **Новым аккаунтам** — один раз при первом входе в Журнал (один раз на аккаунт на этом устройстве).
- **Существующим пользователям:**
  - **флаг выключен** → окно **не показывать**;
  - **флаг включён** → показать **один раз**, поля заполнены текущими значениями (показатель из переключателя, последний счёт, часовой пояс профиля); «Пропустить» ничего не меняет.
- **Второе устройство, где облако уже включено:** настройки придут из облака; окно покажет только вопрос про облако для этого устройства, если на нём ещё не ответили.

## 6. Как настройки влияют на существующие экраны

| Настройка | Что меняется |
|---|---|
| Показатель по умолчанию | с чего открываются Журнал, аналитика, отчёты (сейчас всегда R); переключатель в Журнале остаётся |
| Главный счёт | какой счёт выбран в новой сделке и в мастере импорта (сейчас — последний использованный) |
| Сессия | подставляется в новую сделку |
| Часовой пояс | как сейчас: день сделки в таблице, календаре, итогах дня |

## 7. Риски

- **Окно мешает.** Показывается один раз, есть «Пропустить», Журнал не блокирует, не появляется поверх открытой сделки.
- **Показатель «%» у счёта без стартового баланса** — показываем деньги, когда процент посчитать нельзя (как уже сделано для R).
- **Настройки «новее побеждает» без диалога.** Если поменять показатель на двух устройствах, останется последний. Это оформление, потеря невелика.
- **Ответ «Нет» на устройстве с очередью или конфликтами.** Очередь и конфликты остаются на устройстве, ничего не теряется. При «Да» позже обмен продолжится.

## 8. Тесты

- **Юнит:**
  - чтение и запись настроек, значения по умолчанию;
  - перенос текущих значений для существующих пользователей;
  - запись в `journal_settings` и обратно, «новее побеждает»;
  - ответ «Нет» = облако на этом устройстве не используется; «Да» → автоматическая первая загрузка;
  - изоляция: настройки и ответ про облако одного аккаунта не видны другому.
- **Подсказка «?»:** открывается наведением, фокусом и нажатием; закрывается по Esc и повторному нажатию; связана с вопросом для диктора; на 360px не обрезается.
- **e2e:**
  - новый аккаунт видит окно один раз; «Пропустить» и «Сохранить» работают; настройки меняют экраны;
  - на 360px окно и подсказки целиком на экране;
  - флаг выключен — у существующего пользователя окна нет, у нового нет вопроса про облако;
  - гость — окна нет;
  - на фейковом Supabase: «Да» → загрузка сама с прогрессом и отменой; «Нет» → в облако ни одного запроса; второе устройство получает настройки из облака и видит только вопрос про облако.
- Скриншоты 1440 и 360.

## 11. Блок гостя в «Настройки → Данные на этом устройстве» (решение владельца 2026-10-21)

Делается в **PR 1** этого плана, после «4f пройден».

**Проблема.** У вошедшего пользователя блок «Профиль гостя: Malk, Уровень 2» выглядит как «мой профиль». Ник гостя крупным шрифтом с засечками и уровень путают: у аккаунта уровень другой.

**Как будет у вошедшего пользователя:**

1. Подзаголовок карточки:
   - RU: «В этом браузере хранятся журнал твоего аккаунта и, отдельно, данные гостя».
   - EN: "This browser keeps your account's journal and, separately, guest data."
2. Сначала «Журнал этого аккаунта на устройстве» (счётчики, как сейчас).
3. Затем отдельный блок:
   - **Заголовок:** «Гость на этом устройстве» / "Guest on this device".
   - **Метка рядом:** «Не связан с аккаунтом» / "Not linked to your account".
   - **Поясняющая строка:** «Это данные режима «Продолжить без входа». Уровень, XP и сделки гостя не входят в твой аккаунт.» / "This is "Continue without signing in" data. The guest's level, XP and trades are not part of your account."
   - **Строка гостя** — обычный мелкий шрифт, без засечек: «Гость «Malk» · уровень 2 · сделок 3» / "Guest "Malk" · level 2 · 3 trades".
     - **Числа — только из реальных данных гостя** (тот же источник, что сейчас: `summarizeSpace(null)`). Ничего не подставляется и не округляется.
   - **Оформление:** пунктирная рамка, иконка «гость» (силуэт). Без фиолетового акцента и золота, чтобы блок не выглядел как «мой профиль».
   - **Кнопки:** «Экспортировать», «Удалить данные гостя» — как сейчас. «Скопировать в аккаунт» — только существующая кнопка, на тех же условиях. **Новых кнопок не добавляется.** Её поведение — п. 11.1.
   - **Если гостевых данных нет:** «Гостевых данных на этом устройстве нет».
4. **Гость без входа** — как сейчас, только заголовок «Твой гостевой профиль» / "Your guest profile".

### 11.1 «Скопировать в аккаунт»: расхождение с условием владельца — нужен ответ

**Условие владельца:**
- сделки гостя становятся обычными записями аккаунта и идут в облако;
- XP и монеты не переносятся.

**Как сейчас (проверено в коде, `lib/storage/profile-transfer.ts` → `copyGuestToAccount`):**
- кнопка видна, только пока у аккаунта на этом устройстве **нет своего прогресса и сделок**;
- копирует **все** данные гостя целиком: журнал, скриншоты и **игровое состояние** — уровень, XP, монеты (ник и «личность» остаются от аккаунта). e2e `c1-profile-select` это подтверждает: после переноса уровень аккаунта = уровню гостя;
- то же копирование выполняет кнопка «Перенести данные гостя» на экране после знакомства (`/profile-select`).
- **Уйдут ли скопированные сделки в облако при включённом флаге — не проверено.** Копирование пишет журнал напрямую, мимо очереди отправки. Проверю в PR 1 тестом на фейковом Supabase.

**Варианты (выбор за тобой):**
- **А.** Сделать по условию: копировать только журнал и скриншоты; XP, уровень и монеты не переносить. Сделки — обычные записи аккаунта, уходят в облако обычным путём. Меняется поведение и кнопки в Настройках, и «Перенести данные гостя» после знакомства: путь общий. Тексты кнопок и пояснения поправлю, чтобы не обещали перенос уровня.
- **Б.** Пока не показывать «Скопировать в аккаунт» в Настройках вошедшего пользователя. Вернуть её отдельным шагом вместе с серверными XP и монетами (T12).
- **В.** Оставить как есть (копируется и прогресс). Противоречит условию, поэтому не рекомендую.

**Рекомендация — А.** Она совпадает с принципом «XP и монеты в облако не отправляются и начисляет их только сервер» и не добавляет новых кнопок.

## 12. Как сделано (PR 1 #83, «Настройки по разделам» #85, PR 2 — окно)

- **Вопрос облака** — по решению владельца (2026-10-21) не «Да / Нет», а **«Автоматически / Вручную»**, на каждом устройстве отдельно. В «Вручную» само ничего не уходит и не подтягивается; обмен — по «Синхронизировать».
- **Где настройки:** «Настройки → Журнал» (показатель, главный счёт, сессия, часовой пояс) и «Настройки → Облако и данные» (автоматически / вручную). Окно ведёт туда же («Изменить потом»).
- **Кому окно:** гостям — никогда; один раз на аккаунт на этом устройстве (сохранено или пропущено); ждёт ответа сервера о флаге; облако включено — всем один раз, а если настройки уже пришли с другого устройства (или заданы в Настройках) — только вопрос облака; облако выключено — только новому аккаунту (пустой журнал на устройстве).
- **«Сохранить» + «Автоматически» + журнал ещё не в облаке:** сразу окно загрузки из 4d. Если облако пустое — загрузка начинается сама, с прогрессом и «Отменить». Если в облаке уже что-то есть — обычный выбор «только здесь / только в облаке / отличаются». Кнопка резервной копии JSON — в самом окне настройки.
- **«Пропустить» / закрытие окна** ничего не меняет и окно больше не показывает.
- **Не поверх других окон:** пока открыто окно конфликта или первой загрузки, окно настройки ждёт.
- **Часовой пояс** пока хранится на устройстве; синхронизация через облачный профиль — отдельный PR (решение владельца 2026-10-25, без миграции).
