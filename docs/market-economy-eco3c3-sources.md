# MARKET-ECO-3C.3 — труд, доходы, потребление и производство США

Реализация от main после PR #204. Отдельная read-only проекция для вкладки «Экономика». Календарь уже содержит составной NFP/безработицу, Initial Claims, BEA и Census; их сборщики и записи не изменяются. Безработица отображается одной самостоятельной карточкой текущего ряда вместо вложенного значения в карточке NFP. Цена труда и новые ряды не создают календарных дублей.

## Маршрут, кеш и независимость

`GET /api/market-economy/fundamentals?series=<earnings|unemployment|continuing|income|consumption|retail|production>&range=<latest|history>`.

Метаданные ответа включают seriesId, unit, adjustment и frequency. Период, sourceUrl, release date при доказанности, vintage и preliminary/revised/current/initial передаются в каждом наблюдении. RetrievedAt сохраняется при получении исходного документа в серверном кеше, отдельно от даты выпуска и формирования DOL.

Каждая карточка запрашивается независимо; длинная история запускается кнопкой. BEA income и consumption делят discovery и HTML через общий кеш документов. Повторные одновременные чтения одного документа объединяются в рамках экземпляра функции. В BLS latest/history используют один официальный ответ, а latest возвращает одну точку.

Документы BLS и датированные документы BEA кешируются на 12 часов, BEA RSS и остальные документы — на час. Готовый HTTP-ответ имеет CDN TTL 300 секунд и browser TTL 60 секунд. Error/partial/stale/unavailable получают no-store. Ошибки не записываются в успешный документный кеш. В экземпляре функции после сбоя действует минутная пауза; Retry-After 429/503 у источника соблюдается целиком, в том числе для соседней серии того же origin. Между разными экземплярами глобального резервирования запросов нет. Бесплатный BLS v1 имеет общий лимит 25 запросов/сутки на IP, включая другие потребители; TTL снижает расход, но не гарантирует квоту на распределённом Vercel. При отказе серия остаётся недоступной либо показывает прежний подтверждённый снимок со stale.

Все HTTP-запросы ограничены шестью секундами и двумя мегабайтами, редиректы отклоняются. Latest обычно делает один запрос на источник; BEA требует RSS и последний выпуск. BEA history ограничен четырьмя выпусками, которые загружаются последовательно. DOL history делает один POST на ограниченный диапазон. Изменения cron, SQL, Supabase и секретов отсутствуют.

Серверные логи содержат только series, stage/period, категорию и длительность, без URL с параметрами или внутренних сообщений в интерфейсе. Локальный last-good cache не переживает cold start; после него fallback зависит от Next Data Cache. Никакой гарантии внешней задержки не заявляется.

## Пересмотры и ограничения

Previous берётся из того же ответа/выпуска и ровно предыдущего месяца или недели. Пропущенные значения не заменяются нулём. Будущие даты и противоречивые повторения периода отклоняются.

Более старый период/полученный документ не заменяет сохранённый локальный снимок. Изменение значения при той же версии вызывает диагностический конфликт и stale. Новый датированный выпуск может содержать официальные пересмотры Previous; он отображается со своим vintage. BLS API и DOL current data не доказывают первоначальные значения. Они явно представлены как текущие версии рядов, а не исторические первоначальные факты. При конфликте без доказанной новой версии старый last-good снимок удерживается до разрешения/нового периода; межинстансная история конфликтов без БД не сохраняется.

История показывается списком с версией и источником каждой точки. Нет единой линии, соединяющей разные винтажи. Для Census пока доступен только подтверждённый текущий месяц, без имитации длинной истории. При годовой смене базы Fed адаптер продолжает читать опубликованные MoM по заголовкам месяцев, а не вычислять рост из индексов разных баз.
