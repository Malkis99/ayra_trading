# Вход по паролю и своя почтовая отправка — план

Статус: **принят владельцем** (2026-10-20, решения — раздел 11). Кода нет. Миграций нет. Флаг `cloud_sync` не трогаем. Чек-лист 4f на паузе до решения по входу.

## 0. Как сейчас и почему упираемся в лимит

- Сейчас и регистрация, и вход идут **только по коду на почту** (`signInWithOtp` в `lib/auth/auth-context.tsx`).
  - Первый код для новой почты сам создаёт аккаунт.
  - **Каждый вход = одно письмо.**
- Письма уходят через **встроенную почту Supabase**. Это тестовый сервис с очень маленьким лимитом: несколько писем в час **на весь проект**, а не на человека. Точное число — в Supabase → Authentication → Rate Limits.
  - Чек-лист 4f (вход/выход, второй аккаунт, гость) съедает этот лимит за минуты.
  - Новые пользователи упрутся в тот же лимит.
- Ответ Supabase с кодом 429 мы показываем как «Слишком много писем. Пожалуйста, подождите немного» — непонятно, сколько ждать и что делать.

**Цель:** письмо с кодом — только при регистрации и при «Забыли пароль». Обычный вход — почта + пароль, без писем. Плюс своя почтовая отправка (custom SMTP), чтобы и эти редкие письма не упирались в лимит.

Аккаунт при этом **не меняется**: тот же пользователь в `auth.users`, тот же `id`. Поэтому журнал на устройстве (`ayra:<id>:…`), облачные записи и флаг `cloud_sync` (привязан к `user_id`) остаются как есть.

## 1. Регистрация и вход по паролю

### 1.1 Экран входа `/login` — две вкладки: «Вход» и «Регистрация»

**Вход:**
1. Поля «Почта» и «Пароль». У пароля кнопка-глаз «Показать пароль» / «Скрыть пароль».
2. Кнопка «Войти». Писем не отправляется.
3. Ссылка «Забыли пароль?» (раздел 1.4).
4. Подсказка для старых аккаунтов (раздел 2): «Раньше входил по коду и пароля нет? Нажми «Забыли пароль» — придёт код, и ты задашь пароль».
5. «Продолжить без входа» — без изменений.
6. Галочки согласия на вкладке «Вход» больше нет. Согласие даётся один раз, при регистрации.

**Регистрация:**
1. Поля «Почта», «Пароль» (с «Показать пароль»), галочка согласия (текст как сейчас, 16+).
2. Кнопка «Создать аккаунт» → письмо с кодом подтверждения → экран ввода кода (как сейчас: 6–8 цифр, «Отправить код ещё раз» с таймером).
3. Код верный → аккаунт подтверждён и вход выполнен → дальше как сейчас: знакомство (`/awakening`), затем выбор «Перенести данные гостя / Не переносить», если есть гостевые данные.
4. Ссылка из того же письма тоже работает: страница `/auth/callback` остаётся.

### 1.2 Требования к паролю

- **От 8 до 72 символов.** 72 — техническое ограничение Supabase, длиннее он не сохраняет.
- Без обязательных цифр, заглавных и спецсимволов. Пробелы внутри разрешены. Пароль из одних пробелов не принимается.
- Подсказка под полем — одна строка: «Минимум 8 символов. Лучше фраза из нескольких слов».
- Поле «Повторите пароль» не делаем: вместо него «Показать пароль».
- Браузерный менеджер паролей работает: у полей правильные `autocomplete` (`email`, `current-password`, `new-password`).
- Это же правило (минимум 8) владелец выставляет в панели Supabase (раздел 8.2), чтобы сервер проверял так же.

### 1.4 «Забыли пароль»

1. Поле «Почта» → «Отправить код».
2. Ответ **всегда одинаковый**: «Если такая почта зарегистрирована, мы отправили на неё код». Так не раскрывается, есть ли аккаунт.
3. Экран: «Код из письма» + «Новый пароль» (с «Показать пароль») → «Сохранить пароль».
4. Код верный → пароль сохранён, вход выполнен.
   - На других устройствах сессии завершаются (вопрос 4 в разделе 9).
   - На этом устройстве пользователь сразу внутри.
5. Тексты:
   - RU: «Восстановление пароля», «Отправить код», «Новый пароль», «Сохранить пароль», «Пароль сохранён».
   - EN: "Reset password", "Send code", "New password", "Save password", "Password saved".

## 2. Старые аккаунты без пароля (включая твой)

У всех, кто регистрировался до этого шага, пароля нет. Два способа его получить, оба без потери данных.

**Способ А — в Настройках, если ты уже вошёл (писем не нужно).**
1. В карточке «Аккаунт» кнопка **«Создать пароль»**. Если пароль уже есть — **«Сменить пароль»**.
2. Окно:
   - «Новый пароль» + «Показать пароль» → «Сохранить»;
   - для «Сменить пароль» дополнительно «Текущий пароль»: он проверяется до сохранения.
3. Готово: «Пароль сохранён. Теперь можно входить по почте и паролю».

> Ты сейчас вошёл на компьютере и телефоне. Поэтому сразу после выхода этого шага задаёшь себе пароль в Настройках **без единого письма**, и дальше входишь по паролю.

**Способ Б — на экране входа через «Забыли пароль»:** один код на почту, и пароль задан (раздел 1.4).

**Подсказки:**
- на вкладке «Вход» — подсказка из раздела 1.3;
- после входа по старому аккаунту без пароля (через «Забыли пароль» пароль уже будет) отдельного напоминания не делаем.

**Отдельный «вход по коду» убираем.** Его роль выполняет «Забыли пароль»: один код — и пароль задан. Это вопрос 3 в разделе 9.

## 3. Сессия: сколько остаёшься вошедшим

- **Сейчас и после изменений одинаково:** пользователь остаётся вошедшим на устройстве, пока сам не нажмёт «Выйти».
  - Сессия хранится в cookies браузера. Библиотека Supabase (`@supabase/ssr`) по умолчанию держит их долго и продлевает при каждом визите. Ключ доступа живёт около часа и обновляется сам, без участия человека.
  - Повторный вход нужен только после «Выйти», очистки данных браузера или на новом устройстве.
- **Ограничить сессию** (например, выход после N дней бездействия) в Supabase можно только на платном тарифе. Сейчас не предлагаю.
- **После смены пароля через «Забыли пароль»** другие устройства разлогиниваются (вопрос 4 в разделе 9). Это защита на случай, если пароль меняют из-за утечки.
- **Выход не трогает данные:**
  - журнал и прогресс аккаунта остаются на устройстве, как сейчас;
  - «Выйти и удалить данные…» работает как сейчас.

## 4. Своя почтовая отправка (custom SMTP)

### 4.1 Что нужно от тебя

1. **Домен, которым ты управляешь.** Нужен доступ к настройкам DNS у регистратора, например `ayra-trading.com`. Без своего домена письма будут уходить в спам или не будут отправлены.
2. **Адрес отправителя на этом домене**, например `no-reply@<домен>`. Почтовый ящик заводить не обязательно, адрес нужен только как «От кого».
3. **Аккаунт в почтовом сервисе.** Рекомендую **Resend**: самая простая настройка с Supabase, есть бесплатный тариф.
   - Альтернативы: Brevo, Postmark, Amazon SES.
   - Лимиты бесплатных тарифов проверь на их сайтах: я цифры не придумываю.
4. **Имя отправителя**, например «AYRA Trading».

### 4.2 Пошагово, простыми словами (на примере Resend)

1. Зарегистрируйся на resend.com.
2. Domains → Add Domain → впиши свой домен.
3. Resend покажет несколько DNS-записей (TXT и MX: SPF, DKIM). Добавь их у регистратора домена в разделе DNS ровно как показано.
4. Подожди, пока в Resend у домена появится статус Verified. Обычно от нескольких минут до нескольких часов.
5. В Resend: API Keys → Create → права «Sending access» → скопируй ключ. **Никому не присылай, в репозиторий не кладём.**
6. В Supabase: Project Settings → Authentication → SMTP Settings → включи **Enable Custom SMTP** и заполни:
   - Sender email: `no-reply@<домен>`;
   - Sender name: `AYRA Trading`;
   - Host: `smtp.resend.com`;
   - Port: `465`;
   - Username: `resend`;
   - Password: ключ из шага 5.
   - Нажми Save.
7. Supabase → Authentication → Rate Limits → «Rate limit for sending emails»: после включения своей почты лимит можно поднять. Значение выбираешь ты, исходя из тарифа сервиса. Я предложу число, когда увидим лимит тарифа.
8. Проверка: зарегистрируй тестовую почту → письмо пришло от `AYRA Trading <no-reply@…>`, не в спам.

Шаблоны писем (раздел 8.3) настраиваются там же, в Supabase.

### 4.3 Что останется ограниченным без своей почты

- **Вход по паролю работает без писем**, лимит почты на него не влияет. Это главное улучшение, и оно не зависит от SMTP.
- Ограниченными останутся только **регистрация** и **«Забыли пароль»**: на весь проект несколько писем в час. Для теста и тебя одного этого почти хватает. Для новых пользователей — нет.
- Поэтому порядок такой: вход по паролю снимает блокировку чек-листа сразу, своя почта нужна до приглашения людей.

## 5. Понятное сообщение вместо «Слишком много писем»

**Причины 429 бывают разные.** Сейчас всё показывается одной фразой. Будет так:

| Что случилось | RU | EN |
|---|---|---|
| Лимит писем на проект (встроенная почта) | Сейчас нельзя отправить письмо: сработал лимит отправки. Это не ошибка в твоих данных. Повтори примерно через час. Если у тебя уже есть пароль — войди с паролем, письмо не нужно. | We can't send an email right now: the sending limit was reached. Nothing is wrong with your data. Try again in about an hour. If you already have a password, sign in with it — no email is needed. |
| Повторная отправка кода слишком рано | Код можно запросить ещё раз через {sec} с | You can request a new code in {sec} s |
| Слишком много попыток входа | Слишком много попыток. Подожди несколько минут и попробуй снова | Too many attempts. Wait a few minutes and try again |

- «Примерно через час» — потому что у встроенной почты лимит считается за час. **С custom SMTP** текст станет «через несколько минут». Это плейсхолдер, уточним по выбранному лимиту.
- **«Технические детали»** остаются как сейчас: код ответа, время, очищенный текст ошибки без почты и ключей (`lib/auth/error-sanitizer.ts`).
- Кнопка «Отправить код ещё раз» неактивна, пока идёт таймер (сейчас 60 с).

## 6. Безопасность

- **Не раскрываем, зарегистрирована ли почта:**
  - вход: и «нет такой почты», и «неверный пароль» показываются одной фразой «Неверная почта или пароль»;
  - регистрация на уже занятую почту: Supabase не отправляет письмо и не сообщает об этом. Мы показываем тот же экран «Мы отправили код…» и ниже строку «Если у этой почты уже есть аккаунт — войди с паролем или нажми «Забыли пароль»»;
  - «Забыли пароль» — всегда «Если такая почта зарегистрирована…».
  - Исключение: «Почта ещё не подтверждена» при входе. Его показываем только после **верного** пароля, поэтому подобрать почты через него нельзя.
- **Защита от перебора:**
  - сервер: лимиты Supabase на вход и проверку кода (Authentication → Rate Limits, по IP). Мы их не ослабляем;
  - экран: после 5 неудачных входов подряд кнопка «Войти» блокируется на 30 с с текстом «Слишком много попыток…». Это удобство, не защита; защита — на сервере. 5 и 30 — плейсхолдеры;
  - позже, при необходимости: капча (Supabase → Attack Protection, Cloudflare Turnstile). Сейчас не делаем.
- **Что хранится на устройстве:**
  - как сейчас — только сессия Supabase в cookies браузера (ключ доступа и ключ обновления);
  - **пароль не хранится нигде, кроме Supabase**, и там только в виде хэша;
  - мы не пишем пароль ни в localStorage, ни в логи, ни в «Технические детали»;
  - сохранить пароль может только браузерный менеджер паролей, если пользователь сам согласится.
- **Смена пароля:**
  - «Сменить пароль» требует текущий пароль;
  - после «Забыли пароль» другие сессии завершаются (вопрос 4 в разделе 9).
- Секретов в репозитории нет. Ключ почтового сервиса вводится только в панели Supabase.

## 7. Что не должно сломаться

| Что | Почему не сломается | Чем проверим |
|---|---|---|
| **Твой текущий аккаунт** | Тот же пользователь в `auth.users`, тот же `id`. Пароль добавляется к нему, новый аккаунт не создаётся | e2e: аккаунт «по коду» → «Создать пароль» в Настройках → выход → вход по паролю → тот же `id` |
| **Журнал на устройстве** | Пространство `ayra:<id>:…` по тому же `id` | e2e: сделки на месте после входа по паролю |
| **Облачная синхронизация и флаг `cloud_sync`** | Флаг привязан к `user_id`, синхронизация — к сессии. Способ входа на них не влияет | e2e на фейковом Supabase: флаг включён → вход по паролю → значок облака, сделки синхронизируются |
| **Гость («Продолжить без входа»)** | Не меняется. Перенос данных гостя после регистрации — как сейчас | Существующие e2e гостя + регистрация с гостевыми данными |
| **Ссылка из письма** | `/auth/callback` остаётся для подтверждения регистрации ссылкой | e2e `magic-link-new-tab` (адаптируем под регистрацию) |
| **Несколько вкладок** | Синхронизация вкладок (`tab-channel`, `space-channel`) не меняется | Существующие e2e двух вкладок |
| **Выход** | Тот же `signOut` | Существующие e2e |

## 8. Тесты, риски, разбивка на PR, что делаешь ты

### 8.1 Тесты

- **Юнит:**
  - проверка пароля (8–72, не одни пробелы);
  - разбор ошибок: неверный пароль, почта не подтверждена, 429 по типам;
  - «не раскрываем почту» — одинаковые ответы.
- **e2e на заглушке входа (mock):**
  - регистрация с кодом → знакомство;
  - вход по паролю;
  - неверный пароль;
  - «Забыли пароль» → новый пароль → вход;
  - «Показать пароль»;
  - 360 px и 1440 px.
- **e2e на фейковом Supabase.** В фейковый сервер добавим регистрацию с паролем, вход по паролю, восстановление и смену пароля. Сценарии:
  - старый аккаунт по коду → «Создать пароль» → вход по паролю → тот же журнал и облако;
  - лимит писем → понятное сообщение;
  - две вкладки;
  - гость;
  - изоляция двух аккаунтов на одном устройстве.
- Как всегда: tsc, lint, vitest, build, оба набора e2e, CI зелёный. Падения записываются до перезапуска.

### 8.2 Что делаешь ты в панели Supabase (после «ок», по шагам в PR)

1. **Authentication → Sign In / Providers → Email:**
   - **Enable Email provider** — включено, как сейчас;
   - **Confirm email** — включить: регистрация подтверждается кодом;
   - **Minimum password length** — `8`;
   - **Password requirements** — без обязательных символов;
   - **Secure password change** — выключено. Иначе для «Создать пароль» у давно вошедших Supabase потребует ещё одно письмо. Вопрос 5 в разделе 9.
2. **Authentication → Emails → Templates.** В шаблонах «Confirm signup» и «Reset password» должен быть код `{{ .Token }}`. Готовый текст шаблонов RU/EN приложу в PR, ты вставишь.
3. **SMTP** — раздел 4.2, когда будет домен.
4. **Rate Limits** — посмотреть текущие значения и прислать мне скриншот. Поднять лимит писем после SMTP.

Ничего из этого не удаляет данные и не трогает таблицы. Миграций нет.

   - перед слиянием ты делаешь шаги 8.2.1 и 8.2.2 (Confirm email, длина пароля, шаблоны).
   - **После PR C чек-лист 4f снимается с паузы:** вход и выход по паролю писем не тратят.

## 9. Вопросы к тебе

1. **Домен** для адреса отправителя — какой? Есть ли доступ к его DNS?
2. **Пароль от 8 символов** без требований к составу — ок?
3. **Отдельный «вход по коду» убрать** (его заменяет «Забыли пароль»), или оставить ссылку «Войти по коду» как запасной путь? Рекомендую убрать: каждый такой вход тратит письмо.
4. **После «Забыли пароль» выходить на остальных устройствах?** Рекомендую да.
5. **«Secure password change» в Supabase выключить?** Рекомендую выключить: «Сменить пароль» и так требует текущий пароль, а «Создать пароль» доступен только вошедшему.
6. **Блокировка экрана после 5 неудачных входов на 30 с** — ок как плейсхолдер?

## 10. Плейсхолдеры

- 8 — минимальная длина пароля (ждёт ответа на вопрос 2).
- 5 попыток / 30 с — блокировка кнопки «Войти» на экране.
- «Примерно через час» — текст при лимите писем без SMTP; с SMTP поменяем по выбранному лимиту.
- Лимит писем в Supabase после SMTP — выбираешь ты по тарифу сервиса.
