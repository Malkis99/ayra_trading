# Проверки экономических релизов

## Что изменилось

Ускоренный сбор охватывает CPI и Employment Situation США (одна строка календаря содержит NFP и безработицу). Остальные показатели сохраняют прежний сбор. Открытый календарь перечитывает таблицу AYRA примерно раз в минуту в первые 20 минут после значимого релиза с неподтверждённым исходом. Проверки прекращаются при подтверждении результата, потере фокуса или закрытии календаря.

Проверки источника возможны на T+0, +2, +4, +8 и +14 минутах. Каждый запуск существующего сборщика может занять только один доступный слот; пропущенные слоты не догоняются. Один выпуск использует максимум пять запросов в первые 20 минут. CPI использует один GET датированного HTML, Employment Situation — один POST существующего API BLS. После начального окна интервал составляет минимум два часа до конца первых суток, затем минимум сутки до истечения семи дней. HTTP 403 откладывает следующую проверку этого выпуска на сутки. При 429 действует Retry-After с паузой минимум две минуты. HTTP 503 и таймаут расходуют слот, оставляя возможность повторной проверки. Расписание запусков остаётся прежним. Точное время результата зависит от запусков и доступности источника.

Публичное время последней успешной проверки относится к проверке официальных данных по конкретному событию. Отдельно фиксируется запись результата. Ошибки источника и конфликты записи остаются в серверной диагностике. «Официально не опубликовано» поддерживается для двух годовых показателей CPI за октябрь 2026 при совпадении периода и стадии, прямом сообщении BLS об отсутствующей базе и подтверждении в строках официальной таблицы. Обычный сбой, пустое значение и истечение времени дают ожидание или задержку. [Релиз BLS за октябрь 2026](https://www.bls.gov/news.release/archives/cpi_11102026.htm)

Проверки работают в пределах семидневного окна. Прямой серверный доступ к архиву BLS остаётся открытым вопросом. Миграция не заполняет исторические факты. Если архив продолжит возвращать HTTP 403, календарь покажет задержку; подтверждение из альтернативного официального формата относится к отдельной задаче.

## Порядок включения для владельца

1. На локальной или тестовой БД с `0012` запустите `node scripts/test-migrations.mjs`. Убедитесь, что секции L и M прошли. В тестовой среде проверьте поведение с выключенным флагом и затем с включённым флагом после применения миграции.
2. Проверьте статус `0012` в целевой БД с помощью [0012_status.sql](../supabase/checks/0012_status.sql). Убедитесь, что есть актуальная резервная копия. При желании перед применением сохраните результаты [0012_preflight.sql](../supabase/checks/0012_preflight.sql) для сверки. Сравнивайте снимки с учётом возможных записей действующего сборщика между запросами.
3. В SQL Editor нужного проекта Supabase запустите целиком [0013_market_release_checks.sql](../supabase/migrations/0013_market_release_checks.sql). Скрипт использует транзакцию. При ошибке остановитесь и проверьте её причину перед включением флага.
4. Проверьте схему и доступ запросом ниже. Ожидаются `8` полей, `true` для RPC и RLS, `false` для обоих публичных доступов. Повторите проверку `0012`.
5. Только после успешной проверки добавьте `NEXT_PUBLIC_MARKET_RELEASE_CHECKS=1` в Vercel для среды, подключённой к проверенной БД, и выполните сборку этой среды из одобренной версии. Переменная читается при сборке. Без неё работают прежний путь записи и чтение прежних колонок.
6. После следующего CPI или Employment Situation сверьте время вызова сборщика, записи `bls-cpi-check` или `bls-nfp-check` в `market_feed_runs`, поля проверки в `market_events` и обновление открытого календаря. Проверяйте точную задержку по времени релиза и времени записи результата. Запись о вызове или попытке сама по себе не подтверждает публикацию.
7. Чтобы отключить новый путь, удалите флаг или установите `0` и пересоберите приложение. Аддитивные поля и записанные результаты можно оставить в БД.

```sql
select
  (select count(*) from information_schema.columns
   where table_schema = 'public' and table_name = 'market_events'
     and column_name in ('release_outcome','release_reason','release_phase',
       'release_checked_at','release_attempted_at','release_check_until',
       'release_saved_at','release_official_url')) as release_columns,
  to_regprocedure('public.market_release_reserve(text,text[])') is not null
    and to_regprocedure('public.market_release_finish(uuid,boolean,text,timestamptz,jsonb,jsonb)') is not null as rpc_ready,
  (select relrowsecurity from pg_class where oid = 'public.market_release_checks'::regclass) as rls_enabled,
  has_table_privilege('anon','public.market_release_checks','SELECT')
    or has_table_privilege('authenticated','public.market_release_checks','SELECT') as public_attempts,
  has_function_privilege('anon','public.market_release_reserve(text,text[])','EXECUTE')
    or has_function_privilege('authenticated','public.market_release_finish(uuid,boolean,text,timestamptz,jsonb,jsonb)','EXECUTE') as public_rpc;
```
