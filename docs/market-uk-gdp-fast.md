# UK-3A. Быстрая проверка официальных выпусков GDP

Существующий десятиминутный цикл `scope=news` проверяет сохранённые выпуски ONS в окне от T до T+30 минут. T берётся из подтверждённого расписания UK-1 в UTC с учётом GMT/BST. Ориентир первой попытки — 0–10 минут при успешной утренней сверке, наличии слота и отсутствии паузы ONS. Фактическая задержка включает работу планировщика, доступность ONS и время до появления бюллетеня.

Суточный сбор резервирует три GET на списки и до двух на детали. Переносы проверяются прежде фактов. Пока ожидается сегодняшний выпуск, старые факты уступают ему слоты. Если выпусков несколько, сборщик сортирует их по времени, важности и ID. Повтор уступает ещё не проверенному выпуску. Остаток очереди доступен суточному сбору в пределах 14 дней. Неуспешная утренняя сверка закрывает быстрый цикл до следующего дня.

Слот резервируется на 30 секунд и списывается атомарно до отправки. Неопределённый результат списания запрещает отправку. Списанный слот остаётся потраченным после любого сбоя. Транспорт делает один GET без перехода по редиректам. Завершение допускается до двух минут после списания, перепроверяет снимок события и использует RPC 0012. Повтор завершения возвращает сохранённый исход. Для HTTP 429 и 503 учитывается `Retry-After`, включая следующую дату UTC. Для 429 без корректного заголовка действует пауза в час. HTTP 403 приостанавливает ONS до следующего суточного цикла.

## Включение после согласования

1. Проверить Draft PR и результаты тестов. SQL находится в `supabase/review/0014_ons_request_budget.sql` и применяется отдельно владельцем.
2. После Merge проверить production со снятым серверным флагом `MARKET_ONS_FAST_RELEASE`. UK-2 работает по прежней схеме и не вызывает RPC 0014.
3. Отдельно подтвердить применение SQL. В SQL Editor нужного проекта выполнить 0014 одной транзакцией. Сверить RLS, отсутствие доступа у `anon` и `authenticated` и наличие прав вызова у `service_role`.
4. Включить `MARKET_ONS_FAST_RELEASE=1` на сервере перед первым суточным запуском выбранного дня UTC. Выбрать день, когда прежний UK-2 ещё не отправлял GET. Переключение в середине дня может смешать учтённые и неучтённые запросы.
5. После суточного цикла сверить `ons-gdp-schedule` и `ons-gdp-facts`. В день официального релиза сверить `ons-gdp-fast`, HTTP-ошибки, время первой попытки, количество списаний в `ons_internal.slots`, исходный ID и происхождение записанного факта.

Для возврата к UK-2 выключить флаг со следующих суток UTC, после завершения активных попыток. Таблицы 0014 можно оставить для сверки. Уже опубликованные значения хранятся в исходных событиях.

## Проверка

Стандартный Vitest проверяет отказ при потере подтверждения списания, истечении брони и HTTP 429. Для теста отдельных соединений задать `ONS_TEST_PG_MODULE` (путь к локально установленному модулю `pg`) и `ONS_TEST_PG_PORT` (порт отдельного экземпляра PostgreSQL на localhost). Запустить `npx vitest run lib/market/feeds/ons-budget.test.ts`. Тест создаёт и удаляет собственную временную базу. Часы в SQL заменены управляемыми тестовыми часами для проверки полуночи. HTTP-сервер на localhost считает реальные запросы. Установка модуля `pg` в зависимости приложения не требуется.
