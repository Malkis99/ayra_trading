# Market Economy — Compact UI

UI-only ветка от main `0e06438` (после #206). Источники, API, парсеры, freshness, серверный кеш, Supabase, SQL, cron, секреты, UK-3C, Quest Hub и игровые правила не изменены.

## Изменения

- Карточки Growth/Labor и дополнительные показатели используют одну сетку; от 768 px — две колонки, на телефоне — одна. Отступы сокращены, значения и единицы сохранены. Карточки не растягиваются до высоты соседней раскрытой карточки.
- Глобальный выбор 1/3/5/10 лет/максимум удалён. История календарных наблюдений показывает все доступные подтверждённые периоды выбранной стадии по прежнему алгоритму. API и сами исторические наблюдения сохранены.
- Значения, подтверждённый Previous, единицы, период и предупреждения остаются снаружи. Метаданные и образовательный контекст находятся в нативном «Подробнее». Даты, которых нет в контракте, не реконструируются: сохраняется «Не подтверждено».
- История GDP раскрывается пользователем. Длинные Treasury/Monetary/PCE/fundamentals истории загружаются прежними маршрутами только по запросу. Treasury latest теперь виден сразу при открытии экономики: удалён прежний внешний сворачиваемый контейнер, каждый из трёх latest-запросов остаётся независимым. Серверные лимиты и кеш не менялись. Диапазоны Treasury доступны внутри истории своей карточки.
- Начальная загрузка не резервирует пустую область графика. Загруженную историю fundamentals можно скрыть и показать повторно без нового HTTP-запроса.
- Новый маленький график fundamentals использует только полученные наблюдения. Линии не соединяют пропущенные периоды, разные серии, единицы, стадии или винтажи. Для разных датированных BEA-выпусков остаётся список значений с происхождением: общий сопоставимый винтаж не предполагается. Одно наблюдение — только краткое пояснение после запроса истории.
- Клавиатура, focus-visible, семантика summary/details и reduced motion сохранены; иконка disclosure — lucide в текущей палитре AYRA.

## Проверка и скриншоты

Существующие сценарии PCE/CPI/fundamentals/Treasury/Monetary адаптированы к новому расположению сведений; проверки значений и официальных ссылок сохранены.

Снимки `docs/screens/market-economy/compact/{before,after}-{390,1440}-{ru,en}.png` сделаны Playwright. Before — неизменённый production build main. After — UI-ветка. Это изолированные детерминированные e2e-ответы, а не production или новая проверка экономических значений. Неполные CPI/NFP/Claims показывают пустые состояния; Retail проверяет stale. Для сравнения финансов before раскрыт. Панель имеет собственную прокрутку: для полного снимка снимается clipping предков, без изменения данных или карточек. ## Ошибки промежуточных проверок

- `npx vitest run components/market/EconomyHistoryChart.test.tsx`: три новых теста первоначально упали с `ReferenceError: React is not defined`. Причина — classic JSX transform текущего Vitest. Добавлены явные React imports в компонент и тест; повтор — 3 passed.
- Первый целевой e2e (23 сценария): 9 passed / 14 failed. Два `market-bea-pce.spec.ts` и два `market-inflation.spec.ts` — `Error: expect(locator).toHaveAttribute(expected) failed`, `Error: element(s) not found`: ссылка стала доступна после раскрытия. Тесты теперь раскрывают «Подробнее» перед проверкой того же точного официального URL.
- Десять новых `compact economy <width> <lang>` — `Error: expect(locator).toBeVisible() failed`, `Expected: visible`, `Received: hidden`, `Timeout: 5000ms` для Scheduled release. Тест фокусировал вложенный span вместо summary. Исправлен target клавиатуры; таймауты не увеличивались.
- Следующий целевой e2e: 21 passed / 2 failed, оба `market-monetary.spec.ts`, `Error: strict mode violation: getByTestId('monetary-dollar').locator('svg') resolved to 2 elements`. После добавления chevron карточка содержит и иконку, и график. Проверка теперь выбирает `svg[data-economy-chart]`, а не произвольный SVG.
- Песочница запрещала loopback: `Сделана попытка доступа к сокету методом, запрещенным правами доступа`. При повторном старте оставшиеся наши локальные серверы дали `listen EADDRINUSE ... :::54329`. Только эти процессы остановлены, проверки повторены вне песочницы. Это не ошибки production.

Предыдущая нестабильность Journal E2E (из ревью #206) не исправлялась: `Expected ["NAS100", "USDJPY"], received ["GBPUSDUSDJPY", "NAS100"]`, `Timeout 30000ms exceeded while waiting on the predicate`. Успех нового запуска не доказывает устранение прежней причины. Журнал не меняется.

Merge, production deploy и включение MARKET_ONS_FAST_RELEASE выполняться не должны.
