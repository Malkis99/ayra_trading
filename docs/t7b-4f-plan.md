## 1. Что войдёт в PR 4f (код)

3. **Счётчики журнала на устройстве** в «Настройки → Данные на этом устройстве»: «Журнал этого аккаунта на устройстве: счета N, сделки N, стратегии N, заметки N, «Не вошёл» N, планы N». Нужны, чтобы сверить числа с облаком (пункты 4 и 24 чек-листа). Удалённые записи не считаются — так же, как в облачной проверке.

## 2. Что важно знать до включения (ограничения)

- **Синхронизируется только Журнал:** счета, сделки, стратегии, «Не вошёл», планы, заметки, история импорта, основной проп-счёт.
- **Не синхронизируются** (будут позже, отдельными шагами):
  - **скриншоты сделок** — остаются на устройстве, где их добавили (0005);
  - **XP, монеты, уровень, задания, достижения, персонаж и профиль** — на каждом устройстве свои, как сейчас. На телефоне уровень может отличаться от компьютера — это ожидаемо.
- **Гостевые данные** в аккаунт сами не переносятся.
- **Изменения с другого устройства приходят** при открытии приложения, при возврате на вкладку, при появлении сети и в фоне раз в 5 минут. Мгновенно не приходят.

## 3. Команды SQL (выполняешь ты в Supabase → SQL Editor)

Вместо `ТВОЯ_ПОЧТА` подставь почту, с которой входишь в AYRA. В репозиторий почта не записывается.

**3.1 Проверка до включения** (только чтение):

```sql
SELECT u.id, u.email, f.cloud_sync, f.updated_at
FROM auth.users u
LEFT JOIN public.user_features f ON f.user_id = u.id
WHERE u.email = 'ТВОЯ_ПОЧТА';
```

Должна быть одна строка с твоей почтой; `cloud_sync` пустой (`NULL`) или `false`. Если строк ноль — почта написана не так, как при входе.

**3.2 Включить только у тебя:**

```sql
INSERT INTO public.user_features (user_id, cloud_sync)
SELECT id, TRUE FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА'
ON CONFLICT (user_id) DO UPDATE SET cloud_sync = TRUE;
```

Как проверить, что сработало:
- **успех — только** ответ `INSERT 0 1` **и** `cloud_sync = true` в проверочном запросе 3.1;
- запрос 3.3 показывает `1`;
- в приложении после перезагрузки страницы в шапке появился значок облака.

**Если почта указана неверно**, команда вернёт `INSERT 0 0` и **ничего не включится**: такой почты нет среди пользователей. Проверь почту запросом 3.1 (должна найтись одна строка) и повтори.

**3.3 Больше ни у кого не включено:**

```sql
SELECT count(*) AS accounts_with_sync FROM public.user_features WHERE cloud_sync;
```

Должно быть `1`.

**3.4 Сколько записей твоего журнала в облаке** (только чтение):

```sql
WITH me AS (SELECT id FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА')
SELECT 'Счета' AS what, count(*) FILTER (WHERE deleted_at IS NULL) AS live, count(*) FILTER (WHERE deleted_at IS NOT NULL) AS deleted FROM public.journal_accounts WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Сделки', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_trades WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Стратегии', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_strategies WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Заметки', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_notes WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Не вошёл', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_no_trades WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Планы дня', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_day_plans WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Планы недели', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_week_plans WHERE user_id = (SELECT id FROM me);
```

`live` сравниваешь со счётчиками устройства (раздел 1, пункт 3).

**3.5 Откат — выключить синхронизацию:**

```sql
UPDATE public.user_features SET cloud_sync = FALSE
WHERE user_id = (SELECT id FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА');
```

Как проверить, что сработало:
- ответ `UPDATE 1`; запрос 3.1 показывает `cloud_sync = false`; запрос 3.3 — `0`;
- в приложении после перезагрузки страницы значка облака нет, Журнал открывается и работает как раньше: сделки на месте, новую сделку можно добавить.

Что происходит:
- сервер сразу перестаёт принимать запись в облако;
- приложение перестаёт обращаться к облаку в течение 5 минут или сразу после перезагрузки;
- **ничего не удаляется** — ни на устройствах, ни в облаке.

Удалять облачные записи без отдельного решения не нужно. Если понадобится — подготовлю отдельный запрос, выполнишь его только ты.

**Сделки для конфликтов — заранее**

15. **«Взять из облака».** То же со сделкой Y: на B (режим полёта) «B2», на A «A2» → на B окно → **«Взять из облака»** → на A и на B заметка «A2».

**Правка без сети на A, пока на B другая правка (очередь и конфликт)**

16. На A включи режим полёта → в сделке Z впиши заметку «A3» и добавь на «ТЕСТ-СИНК» новую сделку T. Пока A без сети, на B впиши в заметку той же Z «B3». На A выключи режим полёта:

**Удаление на одном устройстве против правки на другом**
