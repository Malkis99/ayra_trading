## 1. Что войдёт в PR 4f (код)

1. **Один длинный сквозной e2e на фейковом Supabase** («день из жизни»): два браузера одного аккаунта; первая загрузка на компьютере; автоскачивание на «телефоне»; создание, изменение и удаление сделки в обе стороны; правка без сети с последующей отправкой; конфликт правка/правка; удаление против правки; импорт файла TradeTrack на одном устройстве — сделки появляются на другом, XP не начисляется; выход с неотправленным изменением; вход другим аккаунтом на том же устройстве — чужих данных нет; выключение флага — приложение работает локально.
2. **Подпись «Скриншот хранится на другом устройстве»** для сделки, скриншота которой нет на этом устройстве (была обещана в 4c, но не сделана). **Исчезает сама**: подпись показывается, только когда файла нет ни на этом устройстве, ни в облаке. Как только в 0005 скриншоты начнут загружаться в облако, файл будет находиться там, и подпись пропадёт без ручной правки. Это проверит тест: «файл есть в облачном хранилище → подписи нет» (облачное хранилище в тесте — заглушка).
3. **Счётчики журнала на устройстве** в «Настройки → Данные на этом устройстве»: «Журнал этого аккаунта на устройстве: счета N, сделки N, стратегии N, заметки N, «Не вошёл» N, планы N». Нужны, чтобы сверить числа с облаком (пункт 4 и 18 чек-листа). Удалённые записи не считаются — так же, как в облачной проверке.
4. **Проверочный SQL** `supabase/checks/cloud_sync_owner.sql` (только чтение) — тот же запрос, что 3.4 ниже.
5. **Документация:** `supabase/README.md` — раздел «Включение синхронизации», `docs/TASKS.md`.

Флаг в PR **не включается**.

## 2. Что важно знать до включения (ограничения)

- **Синхронизируется только Журнал:** счета, сделки, стратегии, «Не вошёл», планы, заметки, история импорта, основной проп-счёт.
- **Не синхронизируются** (будут позже, отдельными шагами):
  - **скриншоты сделок** — остаются на устройстве, где их добавили (0005);
  - **XP, монеты, уровень, задания, достижения, персонаж и профиль** — на каждом устройстве свои, как сейчас. На телефоне уровень может отличаться от компьютера — это ожидаемо.
- **Гостевые данные** в аккаунт сами не переносятся.
- **Изменения с другого устройства приходят** при открытии приложения, при возврате на вкладку, при появлении сети и в фоне раз в 5 минут. Мгновенно не приходят.

## 3. Команды SQL (выполняешь ты в Supabase → SQL Editor)

Вместо `ТВОЯ_ПОЧТА` подставь почту, с которой входишь в AYRA. В репозиторий почта не записывается.

**3.1 Проверка до включения** (только чтение):

```sql
SELECT u.id, u.email, f.cloud_sync, f.updated_at
FROM auth.users u
LEFT JOIN public.user_features f ON f.user_id = u.id
WHERE u.email = 'ТВОЯ_ПОЧТА';
```

Должна быть одна строка с твоей почтой; `cloud_sync` пустой (`NULL`) или `false`. Если строк ноль — почта написана не так, как при входе.

**3.2 Включить только у тебя:**

```sql
INSERT INTO public.user_features (user_id, cloud_sync)
SELECT id, TRUE FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА'
ON CONFLICT (user_id) DO UPDATE SET cloud_sync = TRUE;
```

Как проверить, что сработало: ответ `INSERT 0 1`; запрос 3.1 показывает `cloud_sync = true`; запрос 3.3 показывает `1`; в приложении после перезагрузки страницы в шапке появился значок облака.

**3.3 Больше ни у кого не включено:**

```sql
SELECT count(*) AS accounts_with_sync FROM public.user_features WHERE cloud_sync;
```

Должно быть `1`.

**3.4 Сколько записей твоего журнала в облаке** (только чтение):

```sql
WITH me AS (SELECT id FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА')
SELECT 'Счета' AS what, count(*) FILTER (WHERE deleted_at IS NULL) AS live, count(*) FILTER (WHERE deleted_at IS NOT NULL) AS deleted FROM public.journal_accounts WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Сделки', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_trades WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Стратегии', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_strategies WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Заметки', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_notes WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Не вошёл', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_no_trades WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Планы дня', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_day_plans WHERE user_id = (SELECT id FROM me)
UNION ALL SELECT 'Планы недели', count(*) FILTER (WHERE deleted_at IS NULL), count(*) FILTER (WHERE deleted_at IS NOT NULL) FROM public.journal_week_plans WHERE user_id = (SELECT id FROM me);
```

`live` сравниваешь со счётчиками устройства (раздел 1, пункт 3).

**3.5 Откат — выключить синхронизацию:**

```sql
UPDATE public.user_features SET cloud_sync = FALSE
WHERE user_id = (SELECT id FROM auth.users WHERE email = 'ТВОЯ_ПОЧТА');
```

Как проверить, что сработало:
- ответ `UPDATE 1`; запрос 3.1 показывает `cloud_sync = false`; запрос 3.3 — `0`;
- в приложении после перезагрузки страницы значка облака нет, Журнал открывается и работает как раньше: сделки на месте, новую сделку можно добавить.

Что происходит:
- сервер сразу перестаёт принимать запись в облако;
- приложение перестаёт обращаться к облаку в течение 5 минут или сразу после перезагрузки;
- **ничего не удаляется** — ни на устройствах, ни в облаке.

Удалять облачные записи без отдельного решения не нужно. Если понадобится — подготовлю отдельный запрос, выполнишь его только ты.

## 5. Чек-лист ручной проверки

Два твоих устройства под **одним аккаунтом**: компьютер (A) и телефон (B). Каждый пункт: что сделать → что должно получиться.

**До начала**

1. **Не удаляй данные, пока не пройдёшь чек-лист.** После включения флага не нажимай «Выйти и удалить данные аккаунта с этого устройства» и не очищай данные браузера (кэш, «данные сайтов»), пока весь чек-лист не пройден и ты не сверил числа в облаке и на устройстве (пункт 18). Пункт 14 проверяет только окно предупреждения — там нажимаешь «Отмена».
2. Резервные копии JSON сохранены на обоих устройствах (раздел 4, шаг 2).

**Первая загрузка — компьютер A**

3. Обнови страницу Журнала → в шапке значок «Журнал ещё не в облаке» (облако со стрелкой), в Журнале кнопка «Загрузить в облако».
4. Запиши счётчики из «Настройки → Данные на этом устройстве» (счета, сделки, заметки…). Нажми «Загрузить в облако» → цифры в окне совпадают с записанными. «Загрузить» → «Готово: журнал в облаке» → значок «Сохранено в облаке» (облако с галочкой), кнопка пропала.
5. Запрос 3.4 → `live` по каждой строке совпадает со счётчиками устройства A. **Дублей нет**: число сделок в облаке не больше, чем на устройстве.

**Пустое устройство — телефон B**

6. Войди тем же аккаунтом на телефоне, где журнала этого аккаунта ещё нет → журнал с компьютера появился сам, одно уведомление «Журнал загружен из облака», кнопки «Загрузить в облако» нет. Счётчики на телефоне = счётчики компьютера.
   *(Если на телефоне уже был свой журнал этого аккаунта: значок «Журнал ещё не в облаке» → «Загрузить в облако» → окно «Только здесь / Только в облаке / Отличаются» → «Загрузить». Отличающиеся записи — через окно выбора.)*
7. Шапка на телефоне: все значки помещаются, аватар целиком; панель значка открывается во всю ширину.

**Создание, изменение, удаление**

8. **Создание:** добавь сделку на A → на B вернись в приложение (или подожди до 5 минут) → сделка появилась.
9. **Изменение:** измени эту сделку на B (например, заметку) → на A правка появилась.
10. **Удаление:** удали эту сделку на A → на B она исчезла.

**Без сети**

11. На B включи режим полёта → добавь сделку → значок «Нет сети», в панели «Ждёт отправки: 1» → выключи режим полёта → значок «Сохранено в облаке» → сделка появилась на A.

**Конфликты на двух устройствах**

12. **Правка против правки:** на B режим полёта → измени сделку X. На A измени ту же сделку X по-другому. Выключи режим полёта, открой Журнал на B → окно «Запись изменена на двух устройствах», обе версии рядом, отличие подсвечено → выбери вариант → через минуту на A и B одинаково.
13. **Удаление против правки:** как пункт 12, но на A удали сделку → на B «На другом устройстве эту сделку удалили, а здесь изменили» → «Взять из облака» → сделки нет ни на A, ни на B. Отдельно проверь «Решить позже»: окно закрылось, значок «Нужен выбор: 1» → значок → «Решить конфликт» → окно открылось на этой же странице.

**Выход с неотправленным**

14. На B режим полёта → добавь сделку → Настройки → «Выйти и удалить данные аккаунта с этого устройства» → окно «Не всё сохранено в облаке: 1 изменение ещё не в облаке» → **«Отмена»**. Выключи режим полёта → значок «Сохранено в облаке».

**Чужой аккаунт**

15. На A выйди и войди другим, тестовым аккаунтом (флаг у него выключен) → значка облака нет, твоих сделок нет. Выйди и вернись в свой аккаунт → значок и все сделки на месте.

**Импорт и скриншоты**

16. Импортируй файл TradeTrack на A → на B появились те же сделки; XP за импорт не начислен.
17. Сделка со скриншотом, добавленная на A → на B у неё подпись «Скриншот хранится на другом устройстве».

**Сверка и откат**

18. **Сверка чисел:** запрос 3.4 → `live` = счётчики на A = счётчики на B. Только после этого можно снова пользоваться «Выйти и удалить данные» и очисткой браузера.
19. **Откат:** выполни 3.5 → проверь по пунктам из 3.5: значка нет, Журнал работает на A и B, сделки на месте, новую сделку можно добавить. Затем снова 3.2, если продолжаем, — значок вернулся, «Сохранено в облаке».
