## 0. Где мы сейчас

- **Облако журнала** (0004) и **скриншоты в облаке** (0005-A/B/C) готовы. Флаг `cloud_sync` включён **только у владельца**.
- **Регистрация и «Забыли пароль» закрыты**, пока нет своей почты (SMTP): `lib/auth/email-sending.ts`. Вход по паролю работает.
- **Удаления аккаунта нет:** в Настройках строка «Удаление аккаунта (скоро)».
- **Что происходит в базе при удалении пользователя** (`auth.users`): все строки журнала, профиль, флаг, журнал аудита удаляются сами (`ON DELETE CASCADE`, миграции 0001–0005). **Файлы скриншотов в хранилище сами не удаляются.** Правило DELETE из 0005 разрешает удалять только файлы удалённых 30+ дней скриншотов и файлы без записи старше 24 часов.
- **В приложении нет серверного ключа** (service role): всё работает от имени самого пользователя.

## 1. Удаление аккаунта (T7d)

### 1.1 Как это видит человек

1. **Настройки → Аккаунт → «Удалить аккаунт».** Окно:
   - что будет удалено: журнал, скриншоты, профиль, персонаж, монеты и XP;
   - что удаление нельзя отменить после срока;
   - предложение сначала сделать **экспорт журнала** (кнопка, экспорт уже есть).
2. **Подтверждение:** ввести свой никнейм (или слово «УДАЛИТЬ», по решению владельца) и пароль, если он задан.
3. **Срок до удаления: N дней** (число — решение владельца, вопрос 1). В это время:
   - вход работает;
   - вверху плашка «Аккаунт будет удалён ДД.ММ. Отменить удаление»;
   - облако журнала не принимает новые данные;
   - флаг облака не трогается.
4. **«Отменить удаление»** в любой момент до срока: всё как было.
5. **После срока** сервер удаляет файлы скриншотов, потом пользователя. Строки журнала и профиль уходят каскадом.
6. **Устройства.**
   - На устройстве, где нажали «Удалить», после срока при следующем открытии: «Аккаунт удалён», выход, данные этого аккаунта в браузере стираются (журнал, скриншоты в IndexedDB, настройки).
   - Другие устройства делают то же при следующем входе или обмене.
   - Гостевые данные не трогаются.

### 1.2 Как устроено на сервере (миграция 0006, применяет владелец)

- **Таблица** `account_deletions`: пользователь, когда попросил, когда удалить, отменено ли. Читать и создавать свою строку может только сам пользователь (RLS).
- **Функции** `request_account_deletion()` и `cancel_account_deletion()`. Срок считает сервер по своим часам.
- **Удаление после срока** — два варианта (вопрос 2):
  - **А (рекомендую). Edge Function по расписанию** с серверным ключом. Ключ хранится только в секретах Supabase, не в коде и не в чате. Раз в сутки функция:
    1. удаляет папку `<uid>/` в bucket `journal-attachments`;
    2. удаляет пользователя через Admin API;
    3. пишет итог в журнал удалений (только id и время, без почты).

    Плюс: человеку ничего не нужно делать после срока. Минус: владельцу нужно один раз добавить секрет и включить расписание (дам пошаговую инструкцию).
  - **Б. Без серверного ключа.** После срока при следующем входе приложение само удаляет свои файлы (расширенное правило DELETE: «аккаунт помечен к удалению и срок прошёл»), затем вызывает `delete_my_account()` (SECURITY DEFINER удаляет `auth.users` своей строки).

    Минус: если человек больше не зайдёт, данные остаются навсегда. Владелец удаляет их руками по SQL-запросу.
- **Проверочный SQL** `supabase/checks/0006_status.sql` (только чтение) и **откат** `0006_*.down.sql`, как в 0005.

### 1.3 Слияние аккаунтов

**Предлагаю отложить из T7d** до Telegram (T7c): сливать сейчас нечего — вход только по почте, один аккаунт на почту. Если владелец считает иначе — отдельный план.

## 2. Порядок выдачи доступа в бету

**Регистрация закрыта до SMTP.** Два пути (вопрос 3).

- **Путь 1 (рекомендую для закрытой беты). Аккаунты создаёт владелец.**
  1. Supabase → Authentication → Add user: почта участника, временный пароль, «Auto confirm». Письма не нужны.
  2. Владелец передаёт участнику временный пароль удобным ему способом, не в публичном чате.
  3. Участник входит по паролю, проходит знакомство и меняет пароль в Настройках → Аккаунт.
  4. Владелец проверяет аккаунт SQL-запросом (только чтение): почта, профиль, флаг. Готовый файл `supabase/checks/beta_participant.sql`.
  5. Владелец включает облако журнала одной командой на почту участника (`supabase/beta/enable_cloud.sql`, по образцу раздела 3 `t7b-4f-plan.md`). Проверка: ответ `INSERT 0 1` и `cloud_sync = true`.
  6. Отключение — одна команда `disable_cloud.sql`. Данные в облаке остаются, устройство продолжает работать локально.
- **Путь 2. Своя почта (SMTP), регистрация открыта по приглашению.** Нужны SMTP, текст писем и решение, как не пускать посторонних (список разрешённых почт). Больше работы, имеет смысл к открытой бете.

**Перед первым участником (условия старта):**
- 0005 применена, проверочный SQL `0005_status.sql` зелёный — сделано;
- лимиты скриншотов на участника из 0005: 200 МБ живых скриншотов и жёсткий потолок 400 МБ на всю папку; контроль — `attachments_usage.sql`;
- T7d слит и проверен — **нужно ли удаление до старта беты или достаточно ручного удаления владельцем** — вопрос 4;
- число участников первой волны — решение владельца (вопрос 5).

## 3. Чек-лист для участников (черновик, в PR — отдельный файл `docs/beta-checklist-ru.md`)

**Перед началом**
- Войти по почте и паролю, сменить временный пароль.
- Проверить значок облака в шапке: «Сохранено в облаке».

**Что проверить (по 5–10 минут на пункт)**
1. Добавить счёт и 3–5 сделок на компьютере → открыть на телефоне → всё на месте.
2. Добавить скриншот к сделке на телефоне → на компьютере он появляется сам.
3. Изменить сделку на двух устройствах почти одновременно → появится окно выбора версии → выбрать одну.
4. Выключить интернет, добавить сделку, включить → сделка ушла в облако.
5. Удалить сделку → «Отменить» возвращает её.
6. Импорт сделок из файла своей платформы.
7. Режим «Вручную» в Настройках → изменения уходят только по «Синхронизировать».

**Как сообщить об ошибке** (канал — решение владельца, вопрос 6):
- что делал, что ожидал, что увидел;
- устройство и браузер;
- скриншот экрана;
- время (примерно).

**Что известно заранее (не ошибки)**
- Монеты и XP пока хранятся на устройстве, а не в облаке: на разных устройствах баланс может отличаться (до 0007).
- В «Вручную» старые файлы скриншотов в облаке убираются только по «Синхронизировать».
- Сообщество, Рынок, Академия — заглушки.
- Не является финансовой рекомендацией: журнал только записывает ваши сделки.
