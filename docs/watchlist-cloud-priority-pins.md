# WATCH-1B.2 — закрепления в Watchlist

Используется серверная модель WATCH-1B.1 и уже применённая владельцем миграция 0017.
Новых миграций, RLS/grants, RPC, зависимостей, cron и production-флагов нет.

## Интерфейс

- Pin/Unpin — кнопка с `aria-pressed`, доступная Enter/Space; отдельный фильтр «Закреплённые».
- Поиск, все шесть категорий и фильтр закреплений пересекаются. Ничего не сортируется автоматически.
- Перестановка меняет только позиции видимых соседей; скрытые инструменты сохраняют позиции.
- Лимит 30, переход к существующему графику и сворачиваемые TradingView Quotes сохранены.
- Удаление из списка не обращается к метаданным. При повторном добавлении действует сохранённое true/false.
- Guest видит объяснение необходимости аккаунта, не открывает хранилище метаданных и не выполняет их запросы.
- Состояния Saved/Pending/Conflict/Error локализованы RU/EN. Legacy-индикатор списка не подтверждает сохранение закреплений.

## Хранение и подтверждения

`lib/storage/watchlist-priorities.ts`: IndexedDB `ayra_watchlist_priorities_v1`, store `accounts`,
ключ — точный userId. В одной readwrite-транзакции хранятся подтверждённый raw-документ и outbox.
Это предотвращает потерю операций при одновременной записи двух вкладок. Guest-записи не создаются.
Сигнальный account-scoped ключ AppStorage уведомляет другие вкладки; он не содержит метаданных.

Каждое действие получает UUID один раз. Для одного инструмента ожидаемые entry revisions образуют
последовательную цепочку; true → false → true не сворачивается в неоднозначный UPDATE.
UI проецирует последний ожидающий выбор, но оставляет Pending. Только проверенный серверный receipt
или readback с тем же operationId/revision удаляет соответствующую операцию из outbox.
Нулевой UPDATE не является успехом. Потерянный ответ безопасно подтверждается повторным чтением.

Операции идут через существующий CAS-helper: до 3 CAS-попыток, без автоматического retry-усиления
Supabase SDK. Каждый HTTP-запрос метаданных ограничен 15 секундами и очищает свой AbortController timer.
Это технический deadline запроса, не гарантия времени синхронизации. После сетевой ошибки очередь
сохраняется. Возобновление — online, возврат во вкладку, ручной Retry, открытие Watchlist и существующий
ритм фоновой проверки 5 минут; тесного бесконечного retry-цикла нет. Storage-сигналы только перечитывают
локальный кэш и не запускают взаимный сетевой feedback loop вкладок.
Контроллер запускается после первого открытия Watchlist и живёт на уровне страницы Market:
переход к существующему Chart не прерывает отправку. До посещения Watchlist другие вкладки Market
не инициируют metadata-запросы. После ухода со страницы очередь остаётся на устройстве до возврата.

Режим cloud_sync=false сохраняет outbox, но не отправляет операции. До первого подтверждённого чтения
нельзя создавать изменение на основе предполагаемого пустого облака. После успешного первого чтения
кэш позволяет поставить действие в offline-очередь. Подтверждённые данные не заменяются более старым ack.

## Конфликты и аккаунты

Разные инструменты можно перебазировать по общему CAS. Конфликт одного инструмента помечает всю
его ожидающую цепочку Conflict, но не блокирует другие инструменты. Автоматического last-write-wins
по часам нет. Пользователь выбирает «Оставить мой выбор» (новое действие после свежего чтения) либо
«Принять из облака» (явное удаление только конфликтующей локальной цепочки).

Контроллер, его асинхронные результаты и UI привязаны к аккаунту и эпохе пространства. A → B → Guest
и даже batched A → B → A инвалидируют старые ответы. Уже принятое локальное действие сохраняется
именно под A, даже если выход случился во время открытия IndexedDB; оно не превращается в Guest/B.
При возвращении A проверяется серверный operationId, а не повторяется неподтверждённая запись вслепую.

Неизвестные поля/инструменты сохраняются буквально существующим helper. Более новая версия облачного
контракта остаётся raw/read-only, очередь не теряется и не отправляется поверх неё. Более новая версия
локальной оболочки также не перезаписывается. Ошибка браузерного хранилища показывается явно.
Старый mergeMarket продолжает игнорировать отдельную строку watchlist_meta; Watchlist/Notes/View не меняют формат.

## Ограничения и откат

IndexedDB зависит от разрешений/квоты браузера. Очистка данных сайта удалит несинхронизированные
локальные действия; подтверждённые закрепления останутся в аккаунте. Между устройствами нет нового
Realtime/polling-канала: применяется описанная фоновая проверка/возврат фокуса. Offline с нуля,
до первого чтения, не разрешает угадывать исходную entry revision. При несовместимом новом контракте
нужно обновление клиента, а не автоматическое затирание данных.

Откат кода не требует down.sql: 0017 и серверные приоритеты остаются, старый клиент их игнорирует.
Не удалять outbox при обновлении/откате. Если вкладка закрылась после отправки, её серверная операция
может завершиться; при следующем открытии она подтверждается идемпотентно. Никакого production SQL,
включения WATCH-2, merge или ручного deployment этот PR не выполняет.
