## 1. Как сейчас: где начисляются XP и монеты

**Важно:**
- XP, монеты, уровень, достижения и задания дня хранятся **только на устройстве**, в пространстве аккаунта. В облако не отправляются — так решено.
- Значит, на каждом устройстве своя копия прогресса, и «первое действие» сейчас тоже считается на каждом устройстве отдельно.
- Загрузка журнала из облака, перенос гостя и «Отменить» **ничего не начисляют сами по себе** — начисление бывает только при действии в интерфейсе.

### Что дало «+10 монет» за правку сделки

- **«Сохранить» у изменённой сделки** вызывает то же начисление, что и новая сделка.
- Если в этот день задание «Запись сделки в журнал» ещё не было закрыто, правка его закрывает: **+40 XP и +10 монет**. Плюс +10 XP за «сделку» (до 3 раз в день, правки тоже считаются).
- Это ошибка: правка не должна ничего давать.

## 2. Правило владельца: «один раз на аккаунт» за первое действие

Монеты (и XP, если они есть за то же действие) — только за **первое** действие каждого вида на аккаунт:
- **ничего не дают:** правка, сохранение, синхронизация, загрузка из облака, «Отменить», перенос гостя;
- журнал, скачанный с другого устройства, не даёт повторного «первого»;
- удалил и добавил снова — тоже не повторно.

### Простая схема сейчас — без миграции и без сервера

**«Первое» считается по самому журналу аккаунта**, включая удалённые записи. Журнал уже синхронизируется между устройствами.

- Сделка — первая, только если в журнале аккаунта нет **ни одной другой** сделки: ни живой, ни удалённой. То же для счёта, стратегии, импорта, заметки, плана, скриншота.
  - **удалил и добавил снова** — удалённая запись осталась (метка удаления), значит, не первое;
  - **журнал с другого устройства** — записи уже пришли, значит, не первое;
  - **перенос гостя** — сам ничего не начисляет; дальше записи уже в журнале, значит, не первое.
- **Начисление только при создании новой записи** в интерфейсе: «Сохранить» у новой сделки, «Создать счёт» и т. п. Правка, обмен, «Отменить» и перенос ничего не вызывают.
- **Отметка на устройстве** (`achievements` в состоянии игры) дополнительно защищает от повтора на том же устройстве.

**Ограничение до сервера:**
- если на двух устройствах **до первого обмена** создать по «первой» сделке, оба получат награду — каждое считает своё;
- сам прогресс (монеты, XP) по-прежнему на каждом устройстве свой.

Это закрывает 0007 (ниже).

### Что нужно изменить в коде (после «ок»)

- `recordLoggedTrade` вызывать **только для новой сделки**, не для правки. Это закрывает найденную ошибку при любом ответе на вопросы ниже.
- Новая функция «первое действие вида X»: проверка журнала, включая удалённые записи, и отметки устройства. Вызов — при создании записи.
- Тесты:
  - правка, «Отменить», загрузка журнала из облака и перенос гостя → 0;
  - удалил → добавил снова → 0;
  - второе устройство после обмена → 0;
  - первая сделка на новом аккаунте → награда один раз.

### Что поменять в 0007 (серверная экономика)

- **Книга учёта** `economy_ledger`: только добавление, на каждую запись — пользователь, сумма XP/монет, ключ награды, время, версия правил.
- **Уникальность** `(user_id, reward_key)`: «первое действие» — ключ вида `first:trade`, `first:account`. Повторная выдача невозможна на уровне базы, с любых устройств.
- **Сервер сам проверяет условие:** функция выдачи смотрит, есть ли у пользователя другие записи этого вида в таблицах журнала (включая удалённые). Клиент сумму не присылает.
- **Баланс и история** = выборка из книги учёта. Вкладка «Монеты» читает её. На всех устройствах один баланс.
- **Переход с устройств:** что делать с монетами, накопленными на устройствах до 0007 (перенести, не переносить, взять максимум) — решение владельца перед 0007.
- **Серверная уборка файлов скриншотов по расписанию** (решение владельца 2026-10-28, из 0005-C). Задача по расписанию на сервере раз в сутки удаляет из bucket `journal-attachments` файлы по тем же правилам 0005: скриншоты, удалённые 30+ дней назад по часам сервера, и файлы без записи старше 24 часов. Зачем: до 0007 уборку делает устройство — в «Автоматически» раз в день, в «Вручную» только по «Синхронизировать», а у того, кто долго не заходит, не делается вовсе. Это приемлемо на бету.

## 3. Вкладка «Монеты» в профиле (план)

**Этап А — сейчас, на устройстве:**
- **Баланс.**
- **«Как получить»** — список действий и сумм из таблицы правил: только «первые действия» и то, что останется по ответам на вопросы.
- **История:** что, когда, сколько; фильтр по типам (первые действия / задания / ежедневная награда).
  - Нужна **запись истории монет**: сейчас в хронике есть только ежедневная награда с суммой монет, у заданий записаны только XP.
  - Без миграции: событие в хронике получает поле `coins`. Старые события остаются без суммы — история монет начнётся с момента внедрения, это будет сказано на вкладке.
- Подпись: «Монеты хранятся на этом устройстве» до 0007.

**Этап Б — после 0007:** баланс и история из серверной книги учёта, одинаковые на всех устройствах.

### Покупка монет за реальные деньги — ⚠ противоречит текущим правилам

Сейчас это **запрещено** правилами проекта:
- Pack v1.0: «Coins только зарабатывается… не продаётся за реальные деньги, не выводится»;
- `AGENTS.md`: «No … real-money payments, or real-money economy. Coins is earned only, never bought».

Поэтому я **ничего не планирую делать**, пока ты явно не решишь поменять это правило (это изменение Pack и `AGENTS.md`). Для решения — что понадобится, если правило поменяется:

- **Платёжный сервис.**
  - Веб: Stripe или «продавец за тебя» (Paddle, Lemon Squeezy — сами платят НДС и налоги в разных странах).
  - Telegram Mini App: цифровые товары внутри Telegram продаются за **Telegram Stars** (правило Telegram).
  - Если будут приложения в App Store / Google Play — их встроенные покупки и комиссия.
- **Серверная экономика (0007) — обязательное условие.** Купленные монеты стоят денег: баланс на устройстве можно подделать, а историю покупок и возвратов нужно хранить на сервере неизменяемо. Отсюда порядок: сначала 0007, потом покупки.
- **Возвраты и споры:** при возврате денег — списание купленных монет компенсирующей записью. Что делать, если монеты уже потрачены (баланс в минус, блокировка покупок).
- **Налоги и бухгалтерия:** НДС / налог с продаж по странам, чеки, отчётность. Проще всего через «продавца за тебя».
- **Юридическое:** оферта и условия покупки; право на отказ от цифрового товара (ЕС, 14 дней — нужна явная галочка); политика возвратов; проверка правил о лутбоксах — кейсы за монеты (Pack D-07) вместе с покупкой монет становятся «платными случайными призами», во многих странах это регулируется.
- **Возраст:** 16+, а для режима 16–17 (Pack 15.3) покупки предлагаю **запретить**: несовершеннолетние, родительское согласие, лутбоксы.
- **Цены:** «10 долларов = 50 монет» — предварительно, в коде и планах только как отмеченная заглушка.

**Порядок этапов (если правило будет изменено):**
1. Исправление начислений и «один раз на аккаунт» на устройстве.
2. Вкладка «Монеты», этап А.
3. 0007: серверная книга учёта, перенос балансов, вкладка из сервера.
4. Решение владельца об изменении правила + юридическая проверка (оферта, налоги, лутбоксы, возраст).
5. Платёжный сервис на тестовых платежах, покупки только 18+, возвраты.
6. Запуск продаж (веб), затем Telegram Stars.

## 5. Решения владельца (2026-10-27)

1. **Задания дня и ежедневная награда остаются с монетами.** «Первые действия» получают отдельную разовую награду на аккаунт.
   - Правка, сохранение, «Отменить», перенос гостя и обмен с облаком **ничего не дают**.
2. **XP за обычные действия журнала** — ответа нет (видимо, потерялся при вставке). Оставляю как сейчас; единственное изменение — правка больше ничего не даёт.
3. **Суммы за «первые действия»** — ответа нет. Отмеченные заглушки в `lib/game-config.ts`.
4. **Задания, которые отмечаются вручную и не проверяются приложением** (прогулка, медитация…): только XP, без монет.
   - Монеты — только у заданий, которые приложение закрывает само по журналу: «Запись сделки», Daily Bias, проверка лимита риска, рефлексия.
   - Такие задания больше нельзя отметить вручную — они закрываются сами.
   - Монеты, уже полученные за ручные задания, **не отнимаются**: правило действует с момента выхода.
5. **Монеты не продаются.** Покупка остаётся только описанием возможного будущего этапа (раздел 3).
6. **При переходе на сервер (0007)** баланс **пересчитывается по правилам из данных**, число с устройств не переносится.
7. **Новое: пока экономика на устройстве** — дневной потолок монет с заданий и ежедневной награды, и защита от смены даты на устройстве.

### Дневной потолок

**Предлагаю 100 монет в день** (`DAILY_COIN_CAP`, одно значение в `lib/game-config.ts`):
- честный максимум сейчас: ежедневная награда до 50 (7-й день серии) + проверяемые задания до 40 = 90;
- 100 — с небольшим запасом: честный игрок в потолок не упрётся, а накрутка даты ограничена.

Разовые награды за «первые действия» в потолок не входят: они бывают только один раз.

### Защита от смены даты — без сервера, насколько это возможно

- Устройство запоминает **самое позднее время**, которое оно видело.
- Если часы перевели **назад** больше чем на 10 минут:
  - монеты и XP не начисляются;
  - день не сбрасывается — задания и ежедневная награда не обновляются;
  - так до тех пор, пока реальное время не догонит запомненное.
- Если часы перевели **вперёд**, без сервера это не определить: можно один раз взять награды «будущего» дня. Но после возврата часов начисления остановятся, пока это время не наступит. Получается, игрок лишь взял свой будущий день заранее — больше, чем по 100 монет за реальный день, не выйдет.
- Полностью это закрывает только серверное время (0007).

## 6. Принципы экономики (коротко)

**Цель:** честно и одинаково для всех. Монеты — знак реальной дисциплины, а не времени, проведённого в кнопках.

**Источники монет:**
- проверяемые приложением задания дня;
- ежедневная награда за серию;
- разовые награды за «первые действия» на аккаунт;
- позже — достижения и челленджи с проверкой на сервере.

**Расходы монет:** гардероб, кейсы (Pack D-07: публичные шансы, лимиты), позже — косметика. Монеты не дают преимущества в рейтинге и не влияют на Академию.

**Что не даёт ничего:** правка и повторное сохранение, синхронизация и загрузка из облака, «Отменить», перенос гостя, импорт сделок (кроме разового «первого импорта»), задания, которые приложение не может проверить (только XP).

**Честное действие** — новое, проверяемое и правдоподобное:
- новая запись (не правка);
- дата не в будущем;
- не дубль (тот же счёт, инструмент, направление, время);
- в пределах дневных лимитов.

**Потолки:** дневной потолок монет, дневные лимиты XP по видам действий (уже есть), каждое задание раз в день.

**Против накрутки:**
- проверки выше;
- защита от смены даты;
- импорт не даёт наград;
- одинаковый скриншот не даёт XP дважды;
- разовые награды — по журналу аккаунта, включая удалённые записи.

**Против неравенства:**
- одни и те же правила и потолки для всех;
- нет покупки монет;
- нет наград за количество сделок сверх лимитов (активный трейдер не получает больше, чем дисциплинированный);
- партнёрские награды — по Pack, детерминированно и не для 16–17.

**Что проверяет сервер (0007):**
- **время** — серверное, а не устройства;
- **каждое начисление** — запись в книге учёта (только добавление) с ключом награды; повтор невозможен;
- **условия наград** — сервер сам смотрит данные журнала, клиент сумму не присылает;
- **дневные потолки и лимиты** — на сервере;
- **баланс и история** — выборка из книги учёта, одинаково на всех устройствах;
- **переход:** баланс пересчитывается по правилам из данных журнала.
