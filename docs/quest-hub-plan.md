## 1. Навигация

Четыре вкладки верхнего уровня, сразу под профилем. Они переключают всё содержимое страницы. Выбранная вкладка хранится в адресе (`/quests?tab=week`), поэтому кнопка «Назад» и ссылки работают.

| Вкладка | Что внутри |
|---|---|
| **Сегодня** (по умолчанию, рядом счётчик 1/3) | Режимы → три миссии → дополнительные задания и привычки. Справа «Прогресс»: неделя, Босс, мои цели. |
| **Неделя** | Переключатель недель → 7 дней с нажатием → панель выбранного дня. Справа: Босс, цели недели, торговые дни. |
| **История** | Дисциплина (серия, щит, активность за 12 недель) → дни с выполненными заданиями. Справа: мои цели, трофеи боссов. |
| **Авторы** (метка «скоро») | Описание будущего раздела и пример каталога. Ни одной рабочей кнопки, наград нет. |

Куда переходят «Путь» и «Дисциплина», с сохранением всех функций:
- **Путь (личные цели)** → карточка «Мои цели» в правой колонке на «Сегодня» и в «Истории». Кнопка «+ Цель» и удаление открывают ту же форму, что сейчас, в боковой панели (на телефоне — снизу). Лимиты прежние: 5 целей, 80 символов.
- **Дисциплина** → верх вкладки «История»: серия и рекорд, щит, карта активности. Клик по дню на карте открывает этот день. Правило серии — коротко в правой колонке.

## 4. Структура вкладок

### 4.1 Сегодня
- **Миссии дня** — три строки. В каждой:
  - номер (после выполнения — ✓);
  - короткое название;
  - **критерий** «Готово, когда: …»;
  - источник подтверждения: «Журнал» зелёный, «Самоотчёт» серый и тише;
  - время;
  - награда;
  - **одна** кнопка, ведущая прямо к действию;
  - статус.
- Статусы миссии:

  | Статус | Как показан |
  |---|---|
  | Выполнено | с временем |
  | Следующий шаг | фиолетовая рамка, главная кнопка |
  | Открыто | обычная кнопка |
  | Только просмотр | при просмотре другого режима |
  | Отложено, заменено | в меню «⋯», как сейчас |

- **Следующий шаг** отмечен прямо в строке миссии, отдельной кнопки в шапке больше нет. Так на экране одна главная кнопка вместо двух.
- **Режимы** Торговля / Учёба / Восстановление / Отдых — компактный переключатель справа от заголовка. Активный режим отмечен зелёной точкой. Смотреть можно любой режим. При просмотре чужого режима появляется строка «Просмотр: Учёба · Сделать активным»; выполненное остаётся на своём месте (`today-study-*`).
- **Отдых** — короткая карточка «Обязательных миссий нет. Серия сохраняется» (`today-rest-*`).
- **Дополнительно и привычки** — ниже миссий, мельче. Лимит самоотчётов — одна строка: «Самоотчёты сегодня: 30 из 90 XP».
- Справочных абзацев на экране нет.

### 4.2 Неделя
- Переключатель «‹ 9–15 ноября ›». Будущие недели недоступны. На прошлой неделе есть кнопка «К текущей неделе».
- **Семь дней.** У каждого: день недели, число, значок режима, «3/3», XP. Нажатие открывает день.
- **Панель дня** (только просмотр, значок 🔒):
  - режим;
  - миссии дня со статусом: выполнено / не выполнено — без штрафа / отложено / заменено;
  - дополнительные задания;
  - замены и пропуски;
  - «Журнал в этот день»: план до первой сделки, сделки со стопом, разбор;
  - итог XP и Coins, самоотчёты из 90.
- **Дни без снимка** (до запуска снимков) показывают только то, что сохранилось. Метка «неполные данные» и прямой текст: «Какие миссии предлагались, режим, замены и пропуски — неизвестны» (`week-old-*`).
- Справа:
  - Босс недели: условия, источник каждого условия, «ваши метки, не проверка»;
  - цели недели;
  - торговые дни.

  У прошлой недели вместо этого — итог Босса и символический трофей (решение 5 UX 3.0).
- Повторно начислить награду или изменить прошлый день нельзя: в панели нет кнопок действия.

### 4.3 История
- Четыре числа:
  - серия и рекорд;
  - щит на неделю;
  - активных дней за 12 недель;
  - полных дней 3/3 — считается только с даты запуска снимков, это подписано.
- Карта дисциплины за 12 недель; нажатие на день открывает его.
- Фильтры: Все / Журнал / Самоотчёты / категории.
- Список **по дням**: дата, режим (если сохранён), задания с источником и временем, итог дня.

### 4.4 Авторы
- Метка «Проект · не работает». Четыре шага: автор → модерация AYRA → каталог со сроком → проверка по данным AYRA.
- Каталог «так будет выглядеть»: три карточки с меткой «пример». Это вымышленные авторы без имён реальных людей. У каждой: условия, срок, «награда после Q4».
- Правила раздела: нет наград за лайки, подписки и просмотры; нет платных подписок.

## 5. Исторические снимки дней

**Цель:** прошлый день можно посмотреть таким, каким он был. Ничего не досочиняется, повторной награды быть не может.

### 5.1 Данные (на устройстве, в `GameState`; миграций Supabase нет)

```ts
/** A closed game day as it was. Written once when the next day starts; never edited. */
interface DaySnapshot {
  v: 1;
  day: string;                    // game day YYYY-MM-DD (account time zone)
  mode: DayMode;                  // the active mode at the end of the day
  modeBeforeRest?: DayMode;
  catalogVersion: number;
  core: string[];                 // the three slots as they were at the end of the day
  bonus: string[];
  offered: string[];              // every quest shown in the active set during the day (before replacements and mode changes)
  done: Record<string, { at?: string; xp: number; coins: number; source: "journal" | "self"; mode: DayMode }>;
  passed: string[];               // «not today»
  replaced: Array<{ from: string; to: string }>;
  modeChanges: Array<{ to: DayMode; at: string }>;
  restDay: boolean;
  shieldUsed: boolean;
  totals: { xp: number; coins: number; selfXp: number };
}
GameState.questDays?: DaySnapshot[];   // newest first
```

Для этого в текущий день нужно дописывать два списка: `offered` и `modeChanges`. Сегодня они нигде не хранятся. Замены уже есть в `questReplacements`.

### 5.2 Правила
1. **Снимок пишется один раз** — в `checkAndApplyDateResets`, при начале следующего дня, до очистки `completedQuestsToday`. Это та же операция под блокировкой (`applyLocked`), поэтому две вкладки не создадут два снимка. Если снимок дня уже есть, он не перезаписывается.
2. **Снимки только для чтения.** Начисление наград их не читает и не меняет. В панели дня нет кнопок действия. Награда за прошлый день невозможна, потому что все функции наград работают только с текущим игровым днём (так уже сейчас).
3. **Часовой пояс.** Ключ дня — тот же `gameDayKey`, он не идёт назад. Если сменить пояс «назад», вчерашний снимок не откроется снова, а новый день не создастся раньше времени.
4. **Пропущенные дни.** Если человек не заходил 3 дня, снимок создаётся только для последнего открытого дня. Дни без захода показываются как «нет записей»: без выдуманных миссий и без штрафных отметок.
5. **Дни до запуска снимков** собираются из `history` (выполненное, время, награды) и `dailyStats` (XP, Coins, число пропусков и замен, отдых, щит). Они получают метку «неполные данные». Предложенные миссии и режим для них не показываются.
6. **«Журнал в этот день»** считается из журнала при открытии. Журнал можно исправить задним числом, поэтому это подписано «по данным журнала сейчас». Награды дня берутся из снимка и не пересчитываются.
7. **Размер.** Снимок — около 0,5 КБ. Срок хранения — `ПЛЕЙСХОЛДЕР` 120 дней (≈60 КБ в localStorage), решение за владельцем [В2]. Старые снимки удаляются; `history` остаётся как сейчас.
8. **Недели.** Аналогичный `WeekSnapshot`: неделя, Босс, итог по условиям, трофей. Пишется один раз при начале новой недели. Трофей не создаётся дважды (решение 5).

### 5.3 Тесты (до показа UI)
- перезагрузка, две вкладки, двойной клик в момент смены дня;
- смена пояса вперёд и назад;
- 3 и 10 пропущенных дней;
- день отдыха, смена режима посреди дня;
- переход с данных до снимков на новые;
- лимит хранения;
- каждая функция наград после открытия старого дня даёт 0.

### 5.4 Как сделано в QH-3

Код — `lib/day-snapshots.ts`, запись — в `checkAndApplyDateResets` (`lib/game.ts`).

Уточнения к проекту:
- **Срок хранения** — 120 последних закрытых дней. Сегодняшний день ещё открыт, снимка у него нет.
- **Чего нет в данных, того нет и в снимке.** Список `incomplete` перечисляет, что снимок не может показать:
  - `set` — набор дня не был сохранён (день начат до Q2);
  - `offered` и `modeChanges` — день начат до QH-3, предложенные задания и смены режима ещё не отслеживались.
- **Режим, в котором выполнено задание** (`done.mode`), известен только для основного задания, оставшегося в своём слоте после смены режима. Для остальных он не записывается; время каждой смены режима есть в `modeChanges`.
- **Итоги дня** (`totals`) берутся из дневной статистики. Это все источники XP и Coins за день, не только задания.
- **Снимок недели** пишется при начале новой недели: Босс недели и итоги дней. Итог Босса по журналу записывает страница «Задания» один раз, уже в следующей неделе: журнал есть только там. Наград за итог нет.
- **Серия при пропущенных днях** в QH-3 не меняется (решение В4: сначала отдельный анализ).

## 6. Ежедневная генерация

**Разделяем два слоя:**

| | Направления дисциплины (3 основные миссии) | Конкретные задания (дополнительно и привычки) |
|---|---|---|
| Что это | Постоянные слоты режима: **Подготовка → Контроль → Итог** (план UX 3.0, раздел 2.2, решения 1 и 4) | Сменные задания из каталога режима |
| Меняются ли | Направления те же каждый день: это рутина, и это честно показано | Да, с защитой от частых повторов |
| Проверка | Только проверяемые данные AYRA во всех режимах (раздел 6.1, решение 2026-11-14; прежнее допущение самоотчёта в восстановлении отменено) | Журнал или подписанный самоотчёт |
| Сделка нужна? | **Никогда** | Никогда |

### Правила
1. Новый игровой день → новый набор. Создаётся один раз и сохраняется (уже так). Перезагрузка и другая вкладка его не меняют.
2. Набор учитывает:
   - активный режим;
   - торговые дни (уже есть);
   - веса из анкеты (уже есть);
   - **последние N дней из снимков** — новое.
3. **Защита от повторов дополнительных заданий:**
   - задание не предлагается снова раньше чем через K дней (`ПЛЕЙСХОЛДЕР` K, решение [В3]);
   - если пул режима слишком мал (у восстановления 7 заданий), берётся задание, которое не показывалось дольше всех;
   - выбор детерминированный: одна и та же история даёт один и тот же набор.
4. Физические задания («Зал», «Плавание») уходят из основных миссий в «привычки» (A7). Их награды не меняются.
5. Пропуск дней: после перерыва создаётся только набор на сегодня, прошлые дни не догоняются. Правила серии не меняются.
   - Важная находка аудита (проверено тестом): дни между последним открытым днём и сегодня **не учитываются**. Был активен 10-го, вернулся 13-го → серия 5 → 6, щит цел. Не был активен 10-го, вернулся 13-го → тратится один щит, а не два. Это текущее поведение; без решения [В4] его не трогаю.
6. Двойных начислений нет: правила наград прежние — одно задание за день, один раз; журнал платит один раз за слот.
7. **Не обещаем «всегда новые задания».** Обещание появится, только когда тест на 90 днях подтвердит правило K для каждого режима. Для маленьких пулов честно пишем: «повторы возможны».

### Тесты
- симуляция 90 дней × 4 режима × 3 профиля: нет повтора раньше K дней, если пул это позволяет;
- основные миссии ни разу не требуют сделки;
- одинаковый набор после перезагрузки и смены пояса;
- пропуски дней;
- переход режима посреди дня (повторяем проверку UX3-1).

### 6.1 Обязательные требования к QH-6 (решение владельца, 2026-11-14)

**Почему.** Сейчас основные миссии могут быть самоотчётами. Владелец отметил их кнопкой «Отметить», они сразу стали зелёными и начислили XP, хотя реальное действие никто не проверял. Для финального Quest Hub это не подходит.

**Требования:**
1. Три основные миссии связаны с **проверяемыми действиями внутри AYRA**, не с самоотчётами.
2. Торговый режим: **Подготовка → Контроль риска → Итог дня**.
3. Ни одно основное задание не требует обязательно открывать сделку.
4. Бэктест засчитывается только за **сохранённые результаты анализа**, не за одно нажатие.
5. Физические упражнения, прогулки и подобное переходят в «Привычки».
6. Проверяемое задание даёт награду **только после подтверждения данных** в AYRA.
7. Самоотчёты сохраняют отдельную пометку «Самоотчёт» и действующий лимит 90 XP в день.
8. За одно действие XP и Coins не начисляются дважды.
9. Ранее заработанные награды и история сохраняются.
10. Новые способы проверки и любые изменения экономики сначала согласуются с владельцем.

**Что значит «проверяемое».** Это значит, что в AYRA сохранены данные, соответствующие правилу: план, лимиты, разбор, заметка нужного шаблона. Правдивость написанного приложение не проверяет. До серверной экономики (Q4) данные хранятся на устройстве. Поэтому полной защиты от фарма до Q4 нет, и мы её не обещаем.

**Общие правила наград:**
- **Один источник — одна миссия.** Одна запись (план, разбор, заметка) закрывает не больше одной основной миссии в день.
- **Ключ награды** — «миссия + игровой день». Повтор, перезагрузка, вторая вкладка и смена режима второй награды не дают (как сейчас).
- **Учитываются только данные с датой текущего игрового дня.** Запись задним числом прошлую награду не открывает (снимки QH-3 только для чтения).
- **Прежние задания и история** сохраняют свои id, награды и записи.

**Таблица: основная миссия → действие → источник подтверждения → условие награды.** Это проект, решения за владельцем.

| Режим | Миссия | Действие пользователя | Источник подтверждения | Условие награды | Есть сейчас? |
|---|---|---|---|---|---|
| Торговля | 1. **Подготовка** | Заполнить план дня в Журнале: направление рынка и уровни | `TradingPlan` игрового дня: `bias` и `levels` | В плане этого дня есть направление хотя бы по одному инструменту **и** хотя бы один уровень [В7] | Частично: сейчас `q_bias` закрывается только по направлению |
| Торговля | 2. **Контроль риска** | Задать лимиты риска и отметить их проверку | `TradingPlan` дня: `limits` и пункт чек-листа `risk_limits_checked` | Задан хотя бы один лимит (риск на сделку, дневной убыток или число сделок) **и** отмечена проверка [В9: оставить ли совпадение по слову «риск» в своих пунктах] | Да, `q_riskcheck` |
| Торговля | 3. **Итог дня** | Заполнить разбор дня | `TradingPlan.review` дня или заметка по шаблону «Итог сессии» за этот день | Разбор завершён, в нём не меньше 40 символов, или заметка «Итог сессии» от 80 символов [В9: пороги] | Да, `q_reflect` |

Одно нажатие не засчитывается [В8] | **Нет**: модуля бэктеста с сохранением результатов в AYRA нет |
| Учёба | 3. **Урок** | Записать вывод из учёбы | Заметка Журнала по шаблону «Урок» | Создана сегодня, текст не меньше N символов [В9] | Частично: шаблон есть, задания нет |
| Восстановление | 1. **Состояние дня** | Отметить состояние и оценку дня | `TradingPlan.review` дня: эмоции и оценка (без текста) | Указаны оценка дня и хотя бы одна эмоция | Частично: поля есть, задания нет |
| Восстановление | 2. **Разбор ошибки** | Разобрать одну прошлую ошибку | Заметка по шаблону «Ошибка недели» | Создана сегодня, текст не меньше N символов [В9] | Частично: шаблон есть, задания нет |

| Отдых | — | Основных миссий нет | — | Серия сохраняется, награды нет | Да |

**Привычки (самоотчёт, только XP, лимит 90 XP в день):** прогулка, тренировка, зал, пробежка, плавание, растяжка, сон без экранов, медитация, чтение, иностранный язык. В основные миссии они больше не попадают.

**Награды.** Новые числа не вводятся без решения [В10]. Предложение — действующая ставка заданий Журнала (40 XP + 10 Coins) для всех девяти миссий. Для новых миссий учёбы и восстановления это изменение экономики, поэтому нужно ваше решение.

**Вопросы владельцу перед QH-6:**
- **[В7]** «Подготовка»: достаточно направления рынка (как сейчас) или нужно ещё хотя бы один уровень?
- **[В8]** «Бэктест»: модуля сохранения результатов нет. Варианты:
  - а) сначала сделать простой модуль «Результат бэктеста» в Журнале (структурированная запись);
  - б) до модуля миссии «Бэктест» нет, её место занимает «Разбор сделок» или «Урок».
- **[В9]** Пороги текста: 40 символов для разбора дня, 80 для заметки «Итог сессии», N для «Урока» и «Ошибки недели». И оставить ли засчитывание своих пунктов чек-листа со словом «риск»?
- **[В10]** Ставки для миссий учёбы и восстановления: те же 40 XP + 10 Coins или другие?
- **[В11]** «Разбор сделок» без сделок: подходит ли замена на «Урок»?

**Окончательная спецификация реализации, симуляция и план PR — `docs/quest-hub-qh6-spec.md`** (решения В7–В11 от 2026-11-14 учтены; новые вопросы В12–В16).

## 7. Creator Quests — будущая архитектура (только проект, после Q4)

До серверной экономики (Q4) ничего не реализуется и ничего не начисляется. Сейчас вкладка только описывает раздел.

| Сущность | Поля (кратко) |
|---|---|
| Автор | id, отображаемое имя, тип (преподаватель / блогер / партнёр), статус проверки AYRA, ссылки на материалы |
| Квест автора | id, автор, **версия**, название, условия, начало и конец срока, лимит «1 раз на аккаунт», статус: черновик → на модерации → одобрен → идёт → завершён |
| Условие | Только проверяемые действия **внутри AYRA**, из закрытого списка проверок: «N разборов сделок», «план до первой сделки N дней», «заметка по шаблону», «итог недели». Засчитываются только действия после вступления в квест |

- **Модерация AYRA** — чек-лист из плана UX 3.0 (раздел 8.4): реальность условий, отсутствие финансовых советов и сигналов, понятный срок, 16+.
- **Запрещено:**
  - награды за внешние лайки, подписки и просмотры;
  - платные подписки на авторов.

  Ссылка на материал автора разрешена, но без награды.
- **Защита от повторов:**
  - уникальный ключ начисления;
  - условие с датой «после вступления»;
  - одна запись журнала засчитывается в один квест автора за раз;
  - новая версия квеста не даёт повторной награды за ту же работу.
