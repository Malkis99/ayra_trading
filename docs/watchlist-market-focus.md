# WATCH-2B — локальный Market Focus

Основание: одобренный проект WATCH-2A `work/watch2a/market-focus-proposal.md` и
его интерактивный макет на 4182. Противоречий функциональному объёму не найдено.
Демо-переключатель аккаунтов, синтетическое стартовое состояние и подпись Saved
из макета не переносятся как реальные данные. В приложении defaults пустые.

## Интерфейс и границы

Один самостоятельный контейнер после списка Watchlist и TradingView Quotes.
Выбор только из канонического Watchlist; поиск, категория и Pin-фильтр не сужают picker.
Четыре селектора: направление, POI, MSS, сессия. Шесть ручных независимых чеков:
POI reached, Liquidity sweep, Displacement, MSS/CISD, Retracement/Test, Reaction.
MSS не выставляет галочку MSS/CISD автоматически. Никаких оценок, котировок,
стратегий, алертов, TP/SL/RR, заметок, сделок, журнала или наград.

Использованы существующие AYRA Select, Checkbox, ConfirmDialog и design tokens.
Локализация RU/EN. Null отображается «Не выбрано», отдельно от Neutral и Session None.
Приоритеты и их облачный статус остаются отдельными от локального статуса Focus.

## Хранилище

IndexedDB `ayra_market_focus_v1`, version 1:

| Store | Ключ | Данные |
|---|---|---|
| entries | [spaceId, instrumentId] | version, revision, direction, poi, mss, session, checklist |
| preferences | spaceId | version, selectedInstrumentId |

spaceId = `account:<uuid>` или `guest`, InstrumentId — существующий стабильный id.
Пустое чтение не создаёт entry. Клиентские timestamps не используются.
revision — локальная последовательность, не серверная ревизия watchlist_meta.
Неизвестные поля сохраняются при patch/reset. Будущая version и невалидная entry
не перезаписываются. Запись неизвестного инструмента не удаляется другими операциями.

Каждая операция применяет минимальный patch к последней записи в одной readwrite-транзакции.
Это сохраняет изменения разных полей из двух вкладок. Для одного поля действует порядок
фактического завершения локальных транзакций. Rapid true → false → true сериализуется.
Параллельные изменения не сравниваются по часам компьютера.

Promise подтверждается только в transaction.oncomplete. Оптимистическое значение имеет
статус «Сохраняем на устройстве», а не Saved. При abort/quota ошибке возвращается последнее
подтверждённое состояние с видимой ошибкой и командой повторного чтения.
Недоступность IndexedDB не ломает список/график/TradingView. Ошибки пользователю не раскрывают
внутренние исключения или account identifiers.

Свой CustomEvent и BroadcastChannel уведомляют вкладки о ключе, а не содержимом.
При отсутствии BroadcastChannel перечитывание выполняется при focus/visibility.
Нет постоянного polling, REST-запросов Focus, MARKET_STORE_EVENT, новых SQL/RPC или cloud outbox.
Существующие `cloud-sync-engine`, mergeMarket, watchlist_meta/CAS не изменены.

## Сохранение, удаление, сброс

- Reload восстанавливает локальное состояние и сохранённый допустимый выбор инструмента.
- Удаление из Watchlist не удаляет запись Focus. Повторное добавление позволяет её открыть.
- Фокус не прыгает автоматически обратно при повторном добавлении; используется текущий выбор.
- При пустом Watchlist — компактное сообщение, без большой неактивной формы.
- Сессия, дата, reload, аккаунт и заполнение всех галочек не сбрасывают данные.
- Reset подтверждает инструмент и захватывает revision. В транзакции revision сравнивается
  с последней entry; mismatch ничего не очищает. Диалог показывает конфликт и требует
  нового просмотра/подтверждения. Другая вкладка не теряет свои непроверенные изменения.
- Cancel/Esc не меняют запись, фокус возвращается на кнопку. Диалог закрывается с
  размонтированием инструмента/space; принятая операция остаётся привязанной к исходной записи.

## Аккаунты и Guest

Компонент размонтирует локальный контроллер по space и auth epoch. Поздние чтения/ответы
старого space не применяются к новому UI, включая A → B → Guest → A и A → B → A.
Принятый клик A может завершиться только в записи A; ни B, ни Guest его не получают.
Guest никогда не переносится автоматически. cloud_sync=false не запрещает локальные записи.
Focus другого устройства/браузера не появится автоматически: облачной синхронизации нет.

## Зафиксированные ошибки разработки

- `npm run build` внутри Windows sandbox: `EPERM: operation not permitted, mkdir '.../.next/static/chunks'`.
  Повтор вне sandbox прошёл; исходники и правила сборки не изменялись ради этого.
- `npx vitest run` в рабочем каталоге захватил старые `work/uk3-pg/node_modules/pg-protocol`
  и выдал `Cannot find module './testing/test-buffers'` / `Cannot find module './testing/buffer-list'`.
  Старые файлы владельца не удалялись. Полный повтор — в чистой копии разрешённых исходников.
- i18n audit первоначально отклонил Order Block / Displacement. Добавлены точные
  утверждённые термины Order, Block, Displacement, CISD в общий словарь допустимой лексики.
  Тест, игровые правила и бизнес-логика не изменялись.
- TypeScript: `afterEach(()=>vi.restoreAllMocks())` возвращал VitestUtils вместо void.
  Callback изменён на блок без возвращаемого значения.
- Первый целевой E2E: `strict mode violation ... resolved to 2 elements` для кнопки «Отмена»
  (иконка закрытия и текстовая кнопка общего ConfirmDialog). Локатор уточнён до текстовой
  кнопки. Другой E2E искал английское gold при RU-поиске по названию/тикеру и получил
  `element(s) not found`; запрос исправлен на существующий тикер XAUUSD. Код поиска не менялся.

## Ограничения и откат

Локальное разделение не является шифрованием/защитой от DevTools или XSS на общем устройстве.
Обычный logout сохраняет данные для повторного входа. Очистка данных сайта удаляет Focus;
private browsing/квота/запрет storage могут препятствовать сохранению. Автоматического backup,
межустройственного merge и интеграции с экспортом/переносом профиля нет.
Действие Reset относится к выбранному инструменту; общей новой функции очистки не добавлено.

Откат кода не требует SQL и не удаляет локальную базу; старые клиенты её игнорируют.
Не применять down-миграции и не изменять существующие облачные данные.
Новых зависимостей, production SQL/RLS/grants/флагов/cron нет. UK-3C, Market Economy,
Quest Hub, Journal, TradingView и рыночные API не меняются.
