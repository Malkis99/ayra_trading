# Journal 2.0 — J2.1: навигация и сделки

28 ноября 2026. Согласован только первый этап; J2.2–J2.6 требуют нового решения владельца.
База: main `9e1d0f5` после merge #230. Оригинальные скриншоты нового ТЗ не предоставлены
в этой задаче; структура взята из текстового описания. Скриншоты ниже — реальный локальный UI
с одинаковыми синтетическими данными, не пользовательские записи production.

- `DashboardTab.tsx`, `JournalKpiStrip.tsx`, `EquityCurve.tsx`, `CalendarTab.tsx`: существующий

## Что изменено

Порядок: **Дешборд → Сделки → План → Заметки → Отчёты → Стратегии → Счета**.
Landing — Dashboard. URL `?tab=analytics` читается и канонизируется в `dashboard`
без потери остальных query/hash. Выбор вкладки создаёт запись browser history;
reload, Back/Forward и клавиатурные Arrow/Home/End восстанавливают выбранную секцию.
Существующий Tabs переиспользован, добавлена соответствующая tabpanel-семантика.

Два вида имеют общий state поиска, выбранного счёта и остальных фильтров:

- **Список**: компактная таблица на desktop, читаемые строки-кнопки на телефоне.
  Инструмент, время профиля, направление, результат, стратегия, Process Score и счёт.
  Клик/клавиатура открывают существующую карточку сделки.
- **По дням**: сводка каждого локального дня и настоящее раскрытие через details/summary.
  Видны итог, количество записей, wins/losses/breakeven/open. Строки монтируются при
  раскрытии, summary остаётся доступным с клавиатуры. Переключение обратно не сбрасывает
  поиск и счёт. Выбор вида сохраняется отдельной account-scoped настройкой устройства
  `ayra_journal_trade_view_v1`; старый density key не переписывается.

Это альтернативные способы чтения тех же Trade, не новые сделки и не облачная схема.
Фильтры не записывают и не изменяют записи. Export «как в таблице» получает ту же полную
отфильтрованную выборку, независимо от вида и страницы.

## Методология итогов списка

- Торговый день определяется **openedAt** в IANA timezone профиля, как в существующем списке.
  Это не перенос результата на closedAt и не изменение финансовой истории.
- Время строки тоже использует профиль. Год виден в заголовке дня.
- В realised итоги входят только закрытые сделки. Открытая строка отмечена «Открыта»;
  она не изображается реализованной победой и не добавляется к дневной прибыли.
- Используется сохранённый net `pnlMoney`, комиссии повторно не вычитаются.
- Деньги суммируются **отдельно по валютам**. Без конвертации и сумм разных валют.
- R — сумма конечных известных rMultiple. Нет значений — «—», неполный набор явно помечен.
- Процентный итог — net P&L / сумма уникальных начальных балансов участвующих счетов ×100,
  только при одной валюте, полном денежном результате и известных положительных базах.
  Это **не Equity/доходность с учётом денежных потоков**; неизвестная база — «—».
- Неполная денежная сумма помечена. Отсутствие данных не заменяется нулём.
- Дни упорядочены хронологически. При сортировке по инструменту/результату меняется порядок
  внутри дня; несопоставимые денежные валюты и R не сравниваются как одно число.
- Сначала группируется вся отфильтрованная выборка, потом применяется мягкая существующая
  граница 50 записей на страницу. Один день не разрезается; большой день может превышать
  этот технический размер. Так итог заголовка соответствует представленному полному дню.

## Проверки и границы

Unit: канонические/legacy tabs, DST и граница дня, 51 запись одного дня, сортировка,
неизменность объектов, неизвестные даты, смешанные валюты, нулевая/неизвестная база,
open/partial/zero, комиссии, реальные layouts и сохранение поиска.
Browser: все семь tabs, URL/reload/Back/Forward, клавиатура, раскрытие, account/search,
открытие quick view, сохранность raw journal, RU/EN × 360/390/768/1024/1440.
Существующие тесты сделок обращаются к `?tab=trades` явно после смены landing;
их бизнес-проверки не ослабляются. Тесты импорта используют новое название «Дешборд».

Фактические результаты, CI и HEAD публикуются в Draft PR после окончания проверок.
Screens: `docs/screens/journal-2-1/before` и `after`.

Production, SQL/RLS, Supabase Auth, cloud sync, защитные flags, Q4.7 и экономика не меняются.
Новых зависимостей, миграций, cron или ручного deployment нет. Merge — только владелец.
