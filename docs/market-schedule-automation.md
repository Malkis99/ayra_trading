# Постоянное обновление официальных расписаний

Решение владельца после #151 и PPI: каждый однажды подключённый показатель должен получать новые
официально опубликованные даты без ежегодного редактирования массивов. Это требование к следующим
подключениям и план отдельных небольших PR, **не разрешение переписать другие сборщики в PPI PR**.

## Приоритеты

На06.11.2026 GET200, в текущем окне подтверждены поддерживаемые записи до05.03.2027. Отдельно решить ограниченность версий переносов и flash/GDP/HICP initial, не заполнять их latest-only данными |

Порядок после PPI: **сначала JOLTS**, затем CPI/Core CPI и остальные BLS. Новый этап начинается только
по команде владельца; эти пункты не реализованы в PPI PR. Дальнейшее расширение DOL/EIA/BEA,
США → ONS/BoE → Германия → еврозона → официальные новости → рыночные уведомления сохраняется.

## Общий договор для каждого адаптера

- Автоматически находить опубликованное расписание нового периода/года на официальном ресурсе.
  Не получать вымышленные даты подстановкой в недельный/месячный шаблон. Указывать фактический горизонт,
  а не обещать годы, которых источник ещё не опубликовал.
- Сначала подтвердить разрешённый серверный доступ и права. HTML, ICS, JSON, PDF — допустимые бесплатные
  официальные форматы при проверенном соответствии, но доступ через web-поиск не доказывает fetch из Vercel.
- У каждого следующего PR — точный budget HTTP: частота штатных запусков не увеличивается; общий feed
  по возможности заменяет несколько загрузок. Не выполнять цепочку fallback-запросов сверх согласованного budget.
- Сохранять last-known расписание в существующей БД. HTTP403/429, недоступность и пустой/сломанный ответ
  не удаляют события и не создают отмену. Ошибки изолированы и попадают только в закрытую диагностику.
- Сохранять period-based IDs/identity из0012 при переходе с ручного источника. Если появились UID,
  не менять ключи старых строк автоматически. Разные метрики/стадии остаются отдельными событиями.
- Перенос принимать только с доказательством актуальности; получение страницы сейчас или изменение ETag
  сами по себе не задают порядок двух конфликтующих версий. STATUS/SEQUENCE/LAST-MODIFIED использовать
  там, где они действительно публикуются. Отсутствие записи не является отменой.
- Сравнивать фактический последний опубликованный/сохранённый месяц с доступным горизонтом и фиксировать
  исчерпание/сокращение горизонта в существующей закрытой диагностике. Новые уведомления/каналы не подключать.
- Тестировать несколько реальных будущих месяцев, декабрь/январь, DST, повтор, перенос, недоступность,
  старые IDs/значения и неоднозначные версии. Синтетические версии/cancellation fixtures явно маркировать.
- Для каждого источника отдельно доказывать initial actual/previous: хорошее расписание не делает
  текущий пересмотренный API-ряд первоначальной публикацией.

## Бесплатные альтернативы и будущие лицензии

Проверенный официальный OMB2027 PDF: `https://www.whitehouse.gov/wp-content/uploads/2026/10/FY2027-PFEI.pdf`.
Он содержит PPI/CPI/Employment Situation и другие индикаторы, но не подменяет оперативные изменения ведомств.
Требуются обнаружение новых документов, контроль версий и точное чтение строк/месяцев, а не копирование
годового массива в код. Изображения/логотипы ведомств не используются.

Платные/лицензионные источники не подключаются и не удаляются из плана: `market-data-future-sources.md`.
