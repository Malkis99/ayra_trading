## 1. Что хранит устройство

`GameState` в `localStorage` пространства аккаунта (`ayra:<uid>:ayra_demo_v1`), читается через `migrateState` (`lib/game.ts`).

- **`level`, `xp`** — `xp` хранит опыт **внутри текущего уровня**: при повышении он уменьшается на порог (`80 + 40·n`). Полный опыт = сумма порогов пройденных уровней + `xp`.
- **`coins`** — баланс. Coins в коде только начисляются; трат не найдено (гардероб, экипировка и прочее их не списывают).
- Записи о наградах — раздел 2.
- **Фикстур реальных старых сохранений в репозитории нет.** Версии видны только по `migrateState`: недостающие поля старых сохранений заполняются значениями по умолчанию.

## 3. Несколько устройств

- **Совпадающие ключи** (`quest:<день>:<id>`, `first:<вид>`, `pq:<runId>`) объединяются **один раз**, а не суммируются.
- **Суммы:**
  - квестов — из записи `history`; при расхождении между устройствами нужно правило (ниже);
  - первых действий — из конфигурации.
- **Остаток без ключей** суммировать нельзя: на двух устройствах может быть один и тот же человек с одними и теми же действиями, синхронизированными через Журнал.

## 4. Варианты для непроверяемого остатка (нужно решение)

**Остаток XP** аккаунта = полный XP устройства − XP с ключами этого устройства. **Остаток Coins** = баланс − Coins с ключами.

| Вариант | Суть | Плюсы | Минусы | Как проверяется |
|---|---|---|---|---|
| **V1. Только подтверждённое** | В облако переносятся только события с ключами; остаток не переносится | Нечего подделать; детерминированно | Уровень и Coins могут снизиться — только с явным показом пользователю | Сумма ключей по всем устройствам без дублей; тесты на фикстурах |
| **V2. Один «legacy»-остаток** | Плюс одна запись `legacy:<аккаунт>` = **максимум** остатка среди устройств (не сумма), помечена «не подтверждено», вступает в силу только после подтверждения человеком | Уровень сохраняется; дубли между устройствами невозможны | Остаток одного устройства принимается на доверии; нужен инструмент подтверждения | Запись в журнале с источником, снимком и тем, кто подтвердил |
| **V3. Пересчёт XP Журнала из облака** | XP Журнала заново по облачным записям (ключ — id записи) по текущим правилам; остаток сокращается до XP времён до облака | Ключи настоящие; дубли исключены | Записи до 0016 без серверной отметки появления; правила начисления менялись; у аккаунтов без облачного Журнала ничего нет | Повторный расчёт даёт тот же результат; сверка с `dailyStats.xpGained` по дням |
| **Пол уровня** (добавка к V1 или V3) | Отображаемый уровень не ниже прежнего, а XP и Coins — только подтверждённые | Никто не теряет уровень | Уровень и XP расходятся до следующего повышения | Тест: уровень после переноса ≥ уровня до |

**Coins:**
- **Правило владельца от 2026-10-27:** Coins пересчитываются из данных, а не переносятся числом. Под это подходит V1 или V3 (Coins с ключами).
- **Остаток Coins:** не переносить; либо по V2 — с подтверждением.

**Расхождение сумм одного ключа между устройствами** (например, правила квеста изменились): взять сумму по нынешним серверным правилам, сумму из записи или меньшую — тоже ваше решение.

## 5. Офлайн-устройства (нужно решение)

Устройство, которое узнало о переносе после окна приёма:
- его снимок **принимается в карантин** (не теряется) с серверным временем приёма;
- в результат сведения **не входит автоматически**;
- пользователь видит, что этот прогресс не перенесён и почему.

## 6. Что не зависит от решения (будет сделано после согласования)

- **Таблица приёма снимков** (`game_imports`, карантин):
  - аккаунт, устройство — случайный id пространства, хранящийся на устройстве;

- **Приём** — одной функцией с проверкой сессии Q4.5-2:

- **Сведение** — чистая функция по каноническим ключам. Результат проверяемый (что принято, что отклонено и почему) и хранится до активации.
- **Инструмент владельца** (не клиентский маршрут) — с журналом действий:
  - выбор аккаунта и проверка состояния;
  - начало переноса;
  - просмотр снимков и предпросмотр сведения;
  - подтверждение активации.
- **Исходные данные не удаляются:** локальное сохранение остаётся, снимок хранится, активация не создаёт пустой профиль вместо неперенесённого.
