## Условия возобновления

1. Повторить проверку точного официального URL в защищённом Preview с сопоставимыми регионом, runtime и заголовками. Зафиксировать HTTP 200, MIME, целостность и SHA-256; проверить извлечение таблицы и совпадение даты, номера выпуска, периода и стадии. Повторить на нескольких датированных документах и измерить доступность около реального релиза. Локальный GET служит сравнением.
2. Проверить официальные варианты с разрешённым доступом. Архив HTML BLS и копия DOL дают датированный vintage. [Публичный BLS API](https://www.bls.gov/developers/) годится для сверки текущих рядов; для первоначального значения нужна подтверждённая версия на дату выпуска. [ALFRED ФРБ Сент-Луиса](https://alfred.stlouisfed.org/) — кандидат для исторической сверки vintage после проверки конкретной серии, доступности, прав и времени появления наблюдения. Он сам по себе не доказывает точные проценты в первоначальной таблице CPI. [Календарь BLS](https://www.bls.gov/schedule/news_release/cpi.htm) и [официальный OMB PFEI](https://www.whitehouse.gov/wp-content/uploads/2026/10/FY2027-PFEI.pdf) пригодны для проверки расписания. Вопрос разрешённой серверной доставки можно адресовать ведомствам.
3. После отдельного согласования использовать один GET на зарезервированный слот `0013`. При проверенном DOL можно выбрать его предпочтительным транспортом. Для независимых пауз и быстрого переключения между транспортами сначала согласовать хранение состояния; действующая пауза относится ко всему выпуску. Зафиксировать точный URL, vintage и контрольную сумму в provenance новых записей. Сохранить проверку `0012`.
4. Историческое восстановление требует отдельного разрешения владельца. Допустимый процесс — получить официальный документ разрешённым способом, сверить контрольную сумму и выпуск, сформировать dry-run по существующим ID, показать diff actual/previous/provenance и проверить на тестовой БД. Только затем владелец одобряет конкретные строки и способ записи. Два годовых статуса требуют отдельного доказательства отсутствия. Конфликты старого provenance выносятся на проверку; защиту RPC сохраняем. Прямые правки production и ручная подстановка фактов сейчас не согласованы.

## Диагностический проект

Изолированный проект `ayra-dol-cpi-probe-20261112` не связан с репозиторием AYRA и Supabase. Vercel принял команду приостановки, однако защищённый `/api/probe` ещё выполнился в 06:43:36 UTC. Повторная проверка 12 ноября в 12:52:59 UTC дала HTTP 410 на точном endpoint. Это подтверждает истечение срока функции и прекращение исходящих запросов из неё; статус приостановки самого проекта Vercel отдельно не подтвердил. Удаление проекта и изменения production не выполнялись.
