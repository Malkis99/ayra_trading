## 2. Находки при сверке решений с кодом `main`

Обе находки касаются только миграции 0020. Она нигде не применена, поэтому исправление возможно без переноса данных. Код я не менял: это работа следующего этапа после слова владельца.

**А. `stylist` подтверждается без доказательства по аккаунту (решение 2).**
- В `game_mig_achievement_plan` ветка `stylist` всегда ставит `verified`, источник `game_rule`.
- Условие на устройстве (`lib/game.ts`, `checkAchievements`): в снаряжении есть хотя бы один предмет. Его выполняет стартовый комплект, но снаряжение можно снять (`unequipSlot`).
- Правило «у каждого есть стартовый комплект» доказано историей git для кода (T3, 2026-10-05). Для отдельного аккаунта сервер пока ничем его не подтверждает.
- **Предложение:** `verified` только при доказательстве по аккаунту. Например:
  - запись о снаряжении в принятом снимке;
  - и/или дата создания аккаунта не раньше выпуска стартового комплекта.

  Иначе — `pending_review` (источник `device_flag`). Какое доказательство достаточно, решает владелец.

**Б. `firstTrade` по любой записи `journal_trades` не совпадает с исходным условием (решение 3).**
- Условие на устройстве: в истории есть выполненный квест `q_tradelog`.
- 0020 ставит `verified`:
  - по событию квеста `q_tradelog` в сверке — совпадает с условием;
  - по событию `first:trade` — **не совпадает**: это отдельная награда первого действия за первую записанную сделку (`FIRST_ACTION_REWARDS.trade`), а не квест;
  - по любой строке `journal_trades` — **не совпадает**: сделка может быть записана, а квест не засчитан (например, импортированные сделки).
- **Предложение:** `verified` только по событию квеста `q_tradelog` в сверке, иначе `pending_review`.

**Проверка остальных правил «запись → verified»** (условие на устройстве → что принимает 0020):

| id | Условие на устройстве | Что принимает 0020 | Совпадает? |
|---|---|---|---|
| `consciousRefusal` | записан день без сделок | `first:noTrade` или строка `journal_no_trades` | да |
| `firstPlan` | ≥ 1 план дня | `first:dayPlan` или строка `journal_day_plans` | да |
| `firstNote` | ≥ 1 заметка | `first:note` или строка `journal_notes` | да |
| `firstReview` | план с `review.completedAt` | строка `journal_day_plans` с `review.completedAt` | да |
| `plans7` | ≥ 7 планов дня | ≥ 7 строк `journal_day_plans` | да |
| `firstPropRules` | сохранены правила проп-счёта | строка `journal_accounts` с объектом `propRules` | да |

Каждое «да» нужно подтвердить тестом с записью, не выполняющей условие (как для `firstTrade`), — это часть исправления.
